## 改写后的版本

MCP 和 Skills 是分工不同，不是强弱之争，老拿"谁更强"比就问错了问题。MCP 是运行时接口,给模型接一个活的外部世界:数据库、浏览器、你司内部系统,协议层握手,连上即用,状态实时。Skills 是打包好的经验,一份 SKILL.md 加脚本,告诉模型"这类任务该怎么干、踩过什么坑",不需要长连接,读一下就会。

MCP 解决"够不到"的问题,Skills 解决"不知道怎么做"的问题。真正浪费 token 的场景是拿 Skills 干 MCP 的活——写一堆 prompt 硬调 API,而不是直接建连接;或者反过来,为了一次性任务去搭 MCP server,过度工程。

要接外部活系统,选 MCP;要复用固定套路,选 Skills。两者别无谓替代。
