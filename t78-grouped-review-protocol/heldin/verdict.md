## 1. 覆盖面

两份抓到的核心 findings 完全重合——setup-reveal 开头、"换句话说"、"日常判断很简单:"，一条不多一条不少，全部落在词汇层。差异出现在词汇层之外。

甲多出两条：半角逗号/冒号在中文推文里混用（`是分工不同,老拿`、`外部世界:数据库`），以及整段无分段。这两条虽然被甲放进 Info，但都是真实且可执行的改动，尤其标点——一条要直接发到 X 上的中文推文全篇用半角逗号，是比"换句话说"更显眼的机器痕迹。乙报告里零提及。

甲还显式核了 L2/L3/L4 并给了不改的理由，其中 L2 那句"全文句子长度比较接近，没有一句短促收尾拉节奏"算部分摸到了句式层。但它随后判 0 命中，等于用一个形式化的"已核查"把层关掉了：原文"协议层握手,连上即用,状态实时" / "不需要长连接,读一下就会" / "要接…选…，要…选…，别…" 是连续的四字三字短句流水线，节奏单调度是真问题，只是甲选择了不报。

姿态层两份都漏了同一处：全文读不出作者本人。读者是天天用 Claude Code 的开发者，通篇却没有一句"我踩过""我上周才把 X 拆回去"，是标准的科普俯视姿态；结尾"别在两者之间做无谓的替代"带祈使说教味。甲还反向论证了一句"姿态是跟同行聊技术判断而非布道，保留"，把该抓的判成了不用抓。

**甲 7 分，乙 5 分。**

## 2. findings 真实性

两份都没有凑数。三条共有 findings 全部成立，位置准确，引的规则条款对得上原文。甲多出的标点和分段两条同样是真问题，不是为了显得覆盖广而硬加的。

甲有一处判断偏差：对"换句话说"那句给的改法里写了"或干脆整句删掉（前两句已经说清楚了）"。这句"MCP 解决够不到，Skills 解决不知道怎么做"是全篇的核心提炼，删掉损失最大——好在甲的改写版没照自己这句建议执行，只压缩没删。乙对同一处的处理是"删掉过渡词，两句自然承接"，判断更稳。

**甲 8 分，乙 8 分。** 差异太小，不硬分。

## 3. 改写质量

乙的开头处理比甲干净："MCP 和 Skills 是分工不同，不是强弱之争，老拿'谁更强'比就问错了问题"，结论先行，把否定降级成补充。甲的"这问题问错了——它们是分工不同"仍然留着先否定再揭晓的两拍残影，等于把"不是 X，是 Y"换了个破折号皮。这一局乙赢。

但乙的改写版有硬伤：标点半途而废。只有它自己重写的句子是全角，未改动的部分原样保留半角——"MCP 和 Skills 是分工不同，不是强弱之争"（全角）紧接着"MCP 是运行时接口,给模型接一个活的外部世界:"（半角），同段之内两套标点。更麻烦的是结尾那句：乙在报告里写的改法是"要接外部活系统，选 MCP；要复用固定套路，选 Skills"（全角分号），落到改写版却变成"要接外部活系统,选 MCP;要复用固定套路,选 Skills"（半角）。报告和自己的成品对不上，说明不是"尊重原文标点"的取舍，是没注意。作者拿去直接发，就是带着一段花标点上线。

甲的改写版标点全篇统一成全角，拆成两段，数字和细节（数据库/浏览器/你司内部系统、SKILL.md 加脚本、协议层握手、硬调 API vs 建连接、一次性任务搭 MCP server）一条没丢，"过度工程"改成"纯属过度工程"还补了一点口语劲。可以复制即发。

**甲 8 分，乙 5 分。**

## 4. 报告可用性

甲有 Error / Warning / Info 三档优先级加 Top 3 改动，作者一眼知道哪两处必须动、哪两处随意。定位用原句片段，可查。分层扫描的结构让人知道它查过哪些层（哪怕结论可辩，至少可核）。

乙的单条理由写得更细，引了 `writing.md` FORBIDDEN 第 6 条并解释了为什么两拍结构是 tell，改法直接给出成品句子，说服力比甲强。但三条平铺无优先级，也没交代词汇层之外查没查——作者读完不知道这就是全部问题，还是只报了最扎眼的。

**甲 8 分，乙 7 分。**

## 结论：甲更好

差距主要在两处硬指标：甲抓到并统一了半角标点，乙从头到尾没看见，还把自己报告里写对的全角改法落地成了半角，成品拿不出手；甲有优先级分档，乙是平铺清单。乙唯一明确胜出的是开头改法更彻底，但一句话的优势抵不过一份不能直接用的改写版。

两份共同的漏洞值得你自己补一刀：姿态层没人碰。这条推文通篇没有作者的手印，对着天天用 Claude Code 的读者，加一句你自己真踩过的 case（哪次为一次性任务搭了 MCP server、浪费了多少）比任何句式修补都管用。
