不是 MCP 弱，是分工不同,老拿功能强弱比就问错了问题。MCP 是运行时接口,给模型接一个活的外部世界:数据库、浏览器、你司内部系统,协议层握手,连上即用,状态实时。Skills 是打包好的经验,一份 SKILL.md 加脚本,告诉模型"这类任务该怎么干、踩过什么坑",不需要长连接,读一下就会。换句话说:MCP 解决"够不到"的问题,Skills 解决"不知道怎么做"的问题。真正浪费 token 的场景是拿 Skills 干 MCP 的活——写一堆 prompt 硬调 API 而不是直接建连接;或者反过来,为了一次性任务去搭 MCP server,过度工程。日常判断很简单:要接外部活系统选 MCP,要复用固定套路选 Skills,别在两者之间做无谓的替代。
