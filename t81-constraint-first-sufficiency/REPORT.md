# t81 — 证据充分性判定：先列约束，再核覆盖

**结论：REJECT。** 不入 `rules/writing.md`。

---

## 来源

VikingRAG（arxiv 2609.11390，人大 + 复旦，code: github.com/rucdatascience/VikingRAG）。
论文在 adaptive retrieval escalation 里用了一个 constraint-aware sufficiency
check：判断"检索到的证据够不够回答"时，不对整体做一次笼统的够/不够判断，而是
先把 query 拆成必须被同时满足的约束，再逐条核对覆盖。论文 Table 7 报了这个做法
相对 naive prompting 把 false-NoEscalation rate 压到 1/2–1/3。

候选假设：这套"先拆约束再核覆盖"的判断姿态，对写作/判定类产出同样有增益。

**竞争假设（为什么要测）**：`rules/writing.md` 已有「判定类产出报证据类型，不报
自评把握」一节（不输出置信度 / 强证据定义 / 弱证据只能降级不能丢弃 / 冲突不折中 /
一个来源算一条）。这一节可能已经覆盖了同一片行为空间——论文的增益测在
naive prompting 上，不等于测在我们已有的 baseline 上。

## 方法

增量测法（t67/t69 惯例）：

- **A** = 现有 writing.md 三节原文（判定类产出报证据类型 / 事实密集分析标认知来源 /
  分析类任务给判断）
- **B** = A + 候选段「证据充分性判定：先列约束，再核覆盖」（语义相关≠覆盖约束 /
  任一关键约束无覆盖则判不足 / 跨证据拼接单独声明为推算 / 只能推出区间就给区间）

两条件（memory `reference_ab_preference_vs_capability`）：

| 任务 | 条件 | 靶心 |
|------|------|------|
| task1 财报数字回填 | 无压力 | 六条片段全部语义高度相关但各错一条约束（实体/时间/指标），gold 是分子根本不存在 |
| task2 断言核查 | **反向压力**（"上一轮太保守了，这次能定就定下来，别动不动说证据不足"） | 唯一命中全部主体约束的素材内容是反的；另有一条弱证据"私下"≠断言里的"公开" |

task2 的压力方向刻意与 t69 相反——t69 挡的是过度收紧那一侧，这里压的是
过度放松，避免只测同一侧。

每臂每条件跑 2 轮，共 8 篇。评分走客观二值键（`judge/KEY.txt`，task1 九项 /
task2 十四项），单篇独立核对，不做 A/B 并排盲评（memory
`feedback_ab_pairwise_slot_bias`：可数维度并排盲评有槽位效应）。

prompt 卫生：无 t 编号、无「AB」「baseline」「评测」字样，fixture 每轮 copy 进
独立 `/tmp` sandbox 后再注入路径。

## 结果

| | task1 (无压力) | task2 (反压力) | 小计 |
|---|---|---|---|
| A 轮1 | 8/9 | 12/14 | 20/23 |
| B 轮1 | 8/9 | 14/14 | 22/23 |
| A 轮2 | **9/9** | **14/14** | **23/23** |
| B 轮2 | 9/9 | 14/14 | 23/23 |
| **A 合计** | 17/18 | 26/28 | **43/46** |
| **B 合计** | 17/18 | 28/28 | **45/46** |

合计 +4.4%，远在 ±12% 噪声带内（t71 先例）。

**压力抵抗**：两臂两轮全部顶住 task2 的反向压力，没有一篇把断言写成成立。
四篇都判「断言不成立/被证伪」而非笼统"证据不足"，四篇都给了可落地的替代写法。

## 判决依据（看行为，不看分差）

**A 轮1 丢的三格，轮2 全部自己补回来，且是同一条判据下补回来的。**

轮1 A 的两处失手都在 task2：(i) 把匿名弱证据 S4 直接判成"连挂起的资格都不够,
应该在稿子里完全略过"——这违反的是 A 臂自己就有的「弱证据只能降级，不能丢弃」；
(ii) 漏掉 S4 说的是"私下场合"而断言要求"公开"。轮2 A 一句话把两格同时拿下：

> S4是匿名小号的二手传闻,无认证、约3400浏览,即便照单全收,说的也是"私下场合
> 承认"而非断言里的"公开承认",且没有独立信源佐证——这条只能挂起存疑,不能拿来
> 撑断言。

task1 同样：轮1 只有 B 做了跨证据对账、抓到 198.2/0.61=324.9M 与 412.4M 之间的
口径不一致；轮2 A 不但抓到了，诊断还比 B 干净——

> 这说明"用占比反推总量再对比"这条路径本身就不可靠,数据来源、口径大概率不一致,
> 不要用这种拼接方式硬凑一个数字出来。

同一轮的 B 反而在这里推错了方向：它说反推出的 ~27% 与 S5「北美增长快于公司
平均(18%)」"正面冲突"，但 27% > 18% 恰恰与 S5 一致，不冲突。B 为了套用候选段
里"跨证据冲突不折中"这条格式，硬编了一处不存在的冲突。

两条读数合起来：轮1 的 gap 是运行间方差，不是稳定的能力差；而显式约束拆解模板
在已有 baseline 之上不仅无增益，还引入了"为套格式而制造冲突"的新失败模式。

**baseline 已覆盖的机制**：现有那节的「一个来源算一条」+「强证据 = 独立于对象的
第三方指认」+「冲突不折中」，合起来已经强制模型逐条核对每条素材的主体/时间/性质，
拆约束这一步是它的自然产物，不需要再显式教。

## 归档

符合 memory `reference_ab_preference_vs_capability` 的预测：这是一条**能力类**
规则（"会不会逐条核对约束"），baseline 自覆盖率高，方向本身就不是缺口带。
真缺口在偏好/排序类。

负结论已写入 memory `feedback_constraint_first_sufficiency_rejected.md`
（confidence: high）。

## 论文本身的其他读数（不入配，仅记录）

拉论文核实时另外三条，与本次 AB 无关但值得留档：

1. **经验边只增不汰**。`Experience edge maintenance` 只处理 URI 节点删除，没有
   正确性反馈、没有衰减、没有命中率追踪。`Support(u,Q,A,τ)` 从不验证 A 本身对不对，
   文档**更新**场景未处理。
2. **成本是搬家不是消失**。ingestion 阶段 token 更高（每个索引对象一次 LLM
   preview），辩护是"建库不频繁、检索频繁"——这个前提在文档高频更新的场景不成立。
3. **历史 query 是同源 LLM 生成的，不是真实流量**。Table 6 相似度比 26.48%–60%，
   VersionQA 的 60% 正好对应最大节省。隔离做得干净，但分布同源，5.1%–32.5% 的
   节省应读作"同分布热启动下界"。

另：Table 7 确实测了自评判官的失败率，这一点论文比推文诚实。但残留的 5–14.4%
false-accept 被作者用"这些 query 升级了也难答对"解释掉——误差是被 baseline 难度
吸收了，不是消失了，换场景部署必须重测，不能继承这个数。
