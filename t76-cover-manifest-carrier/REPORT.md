## 逐条增补的处理

### 1. 载体信号（`references/carriers.md`）→ KEEP

确定性最干净的一条：A 的 prompt 里 mockup 摄影感 / 设备外框 / 画中画取景框三类负面约束**一条都没有**，B 三条全有。s4 里 A 同样漏了 `screen_cover` 载体约束，严苛评审 J3 判这在 5:2 屏幕封面下「确有价值」。盲评三票同向。这条补的是原来根本不存在的一格，没有 baseline 已覆盖的问题。

### 2. Recipe Manifest → KEEP

s3 是全场最大差距（+46/150）。A 在「两张要一眼看出是同一个系列」这个用户唯一强调的硬要求上翻车得很彻底：给两期换了两种背景色（雾霾蓝 / 暖灰）、以风格禁角标为由删掉期号、还把 06 期标题擅自改写成「三个脚本，一条命令」当唯一上屏文字——而 A 自己开头写的是「两张标题原文直接当唯一主标题上屏」，说的和交付的是两回事。色值 Jaccard 100% vs 67% 是同一件事的机器读数：先填死配方再编译，两期的色板就不会各自漂。

顺带一个 A 独有的实操缺陷（J1/J3 独立发现）：A 把「出图前自查」整段写在了 ``` 代码块**内部**、`Generate only one final image.` 之后，用户整段复制会把内部路径一起喂给生图模型。

### 3. Retry 冻结 → KEEP，但补一条收窄

**这是本轮唯一指标与盲评相反的一格，也是最值钱的发现。**

B 冻结得干净（保留 98%、维度外改动 0 行），A 动了 8 行、其中 1 行在诊断维度外。按冻结纪律 B 赢。但盲评三票全给 A，理由一致：B 合法地只插了一行，可那一行只给了一条聚合的「25 字」总数——模型数不准总字数是常态，对「标题下多个句号」几乎没有约束力；A 虽然多动了几行，给的是 A/B/C 逐层恰好字数 + 「画完即停」+ 总数自查，是真能压住漂移的杠杆。

更硬的一击：B 在插入那行时把角标写成「管理笔记04」，吞掉了用户原文的空格，与它自己保留的 C 层「管理笔记 04」打架——**它违反了自己声称的逐字冻结**。

诊断：条款只约束了「哪些地方可以变」，没约束「变的那一处够不够硬」，于是「只改一个字段」被读成了「只补一句话」。s4 里 B 载体信号加对了、字数却数错 38/39，是同一个口子的另一种长相。

已对 SKILL.md 的 Retry 段做两处收窄（`cover-styles-verify.py` exit 0）：

- 新增第 3 条：**冻结管的是可变面积，不是约束强度**——被诊断那一维要一次加到够硬，文字翻车就拆成 A/B/C 逐层「恰好 N 字符」+「画完即停」，别只给一个总字数。「改一行不等于修好了」
- 原第 3 条（现第 4 条）补：逐字是复制不是照着重打，空格、标点、大小写差一处就不算冻结

**这两条收窄本身未经 AB 验证**——它们是对本轮观测到的具体失效的修补，不是新主张。下轮碰到 retry 场景时留意 s2 那个失效模式是否复发。

## s4 反向场景怎么读

s4 是防「只测 B 甜区」的噪声惩罚格，结论比总分更重要：**克制度三个评审全判 8:8 平**。B 没有因为多了 manifest 就往面向用户的回复里塞流程和仪式段落（确定性读数：prompt 之外只多 63 字符），用户「赶时间、别问我别的」两臂都被尊重，都没追问。B 输的 10 分全在实例级失误（字数数错一位、「横贯画面」与「止步于右三分之一」自相矛盾），不是变量带来的系统性成本。

即：这轮没有观察到「加了配方表就变啰嗦」的副作用。
