# t76 盲评

## 方法

8 份 `outputs/*.md` 去掉臂标记，按场景**独立**打乱成 X / Y 塞进 `/tmp/covjudge/`，连同该场景的原始需求（s2 另附上一版 prompt）一起交给 3 个互不可见的 Opus 评审。评审不知道被测变量是什么、不知道有两套规范、不知道这是 AB test；只被告知「两份来自不同助手的回答，判断哪份对提出需求的人更有用」。

维度（每项 1-10）：需求还原 / 可执行性 / 可验证性 / 贴合诉求 / 克制度。评分纪律里显式写了「不因更长或结构更花给高分，也不因更短给高分」。

三个评审的差异：J1 中性，J2 中性但被点名去查 s3 系列一致与 s4「赶时间」的尊重程度，J3 设定为严苛型（默认怀疑每段是否真有用，显式查形式主义和越界改动）。

## 逐场景理由（取三个评审的交集）

**s1 载体 — B 胜。** 三个评审独立点出 A 自作主张在画面里加了一只手：用户没要人物，手是生图模型最经典的翻车部位，且 A 自己上一句还写着「不额外堆砌物体」。B 则把 `screen_cover` 的三条禁止信号（纸张投影 / 设备边框 / 贴墙环境）写全，J3 的原话是这治的是「模型在画关于这张图的照片」。A 唯一独有得分点是防住了标题里的书名号泄漏。

**s2 retry — A 胜，且这是本轮最值得看的一条。** 确定性指标上 B 完胜（保留原样 98% vs 89%，维度外改动 0 vs 1），但盲评三票全给 A。理由三个评审基本一致：B 冻结得很干净，可它给的只有一条聚合的「25 字」总数，模型数不准字数是常态，对「标题下多个句号」几乎没有直接约束力；A 虽然多动了一行，给的是 A/B/C 逐层恰好字数（4/15/7）+「画完即停」+ 总数自查，是真能压住漂移的杠杆。更糟的是 B 在插入那一行时把角标写成「管理笔记04」，吞掉了用户原文的空格，与它自己保留的 C 层「管理笔记 04」打架——**它违反了自己声称的逐字冻结**。A 的失分在末尾多挂了一段用户没问的风格建议（克制度 J1/J2/J3 都判 A 低于 B）。

**s3 系列 — B 大胜，本轮最大差距。** 用户唯一强调的硬要求是「两张一眼看出是同一个系列」，A 给两期换了两种背景色（雾霾蓝 / 暖灰）、又以风格禁角标为由删掉了期号，剩下的统一信号只有抽象骨架。A 还把 06 期标题擅自改写成「三个脚本，一条命令」当唯一上屏文字，用户真正的标题被降级成「不上屏」——而 A 自己开头写的是「两张标题原文直接当唯一主标题上屏」，说的和交付的是两回事。J1/J3 另外都发现 A 把「出图前自查」整段写在了 ``` 代码块**内部**、`Generate only one final image.` 之后，用户整段复制会把 `references/cover-diagnosis.md` 这类内部路径一起喂给生图模型。B 用同色板 + 同骨架 + 同格式期号三重锁系列感。

**s4 克制（反向场景）— A 胜，但不是输在克制度。** 克制度三个评审全判 8:8 平——B 没有因为多了 manifest 就往回复里塞仪式段落，这是这个反向场景最想验的那件事。B 输在两处实例级失误：把总字数写成 38（实际 39），以及「横贯画面」与「止步于右三分之一、未完成部分被留白吞掉」在同一条 prompt 里自相矛盾。B 的独有得分点是补了 `screen_cover` 与 mockup 负面约束（J3 认为 5:2 屏幕封面下确有价值），A 的独有得分点是「不出现任何中文字符」和「不画剪刀」两条护栏。

## 读法

盲评和确定性指标在 s1/s3 完全同向，在 s2 相反、在 s4 轻微相反。相反的两处指向同一件事：**冻结/配方只约束了「哪些地方可以变」，没有约束「变的那一处够不够硬」**。s2 里 B 合法地只改一行，但那一行的约束强度不如 A 大改四行；s4 里 B 载体信号加对了，字数却数错。这不是变量本身失效，是变量留了个口子——处理见 `REPORT.md`。
