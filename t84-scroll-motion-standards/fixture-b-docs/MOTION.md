# 滚动与指针动效标准

## 定位与边界

本文只管**滚动与指针动效**：滚动触发与滚动绑定的区分、视差、sticky 滚动叙事、滚动吸附、滚动缩放、图片序列、横向滚动、指针跟随、多输入等价、reduced-motion 降级。

不管的部分（遵循项目既有动效约定，本文不重复定义）：缓动曲线、时长预算、spring 参数、stagger 间隔、transform-origin、组件级进出场动效、press 反馈、设计 token。本文需要引用这些时只做指引，不复制数值。

## 0. 先分清两种滚动动效

这是全篇的前提。同一个滚轮动作承担两件完全不同的事：

| | Scroll-triggered（进入视口） | Scroll-linked（跟随进度） |
| --- | --- | --- |
| 心智模型 | 按下播放键，之后动画自己播完 | 拖动视频进度条，滚到哪播到哪 |
| 用户停止滚动 | 动画继续播完 | 动画停在当前帧 |
| 用户反向滚动 | 不受影响（默认 once） | 同步倒放 |
| 实现 | IntersectionObserver + CSS transition | `animation-timeline: view() / scroll()` |
| 典型用途 | 标题入场、卡片交错、数据卡 | 视差、滚动缩放、进度条、图片序列 |

**提示词与需求文档里必须写明是哪一种。** 只说"滚动时动画"会让实现方在两者间瞎猜，而两者的失败模式完全不同：triggered 的典型 bug 是反复进出视口反复播放，linked 的典型 bug 是倒放时状态不对称。

**判定**：问一句"用户滚到一半停下来，画面应该停在中间状态吗？" 是 → linked；否 → triggered。

## 1. 实现路径优先级

1. **CSS scroll-driven animations**（`animation-timeline: scroll()` / `view()`）——运行在合成器线程，不占主线程。**但必须写成渐进增强**，见下方兼容性硬约束。
2. **IntersectionObserver + CSS transition**——triggered 类的默认解，也是 Firefox 的兜底路径。不要用 scroll 事件算位置来模拟它。
3. **rAF + scroll 监听**——最后手段。只在需要读取滚动速度、方向差值等 IO 给不了的信息时用，且必须 rAF 节流，禁止在 scroll 回调里直接读 `getBoundingClientRect()` 触发强制同步布局。

### 兼容性硬约束（2026-09 核实）

`animation-timeline` **尚未 Baseline**，卡在 Firefox：

| 引擎 | 状态 |
| --- | --- |
| Chrome / Edge | 115+ 无 flag 支持（2023-07） |
| Safari / iOS Safari | 26 起支持（2025-09），26.4 加入 threaded 执行，26.5 修进度精度与 `animation-play-state` 缺陷（2026-06） |
| Firefox | **stable 仍在 `layout.css.scroll-driven-animations.enabled` flag 后**（截至 Firefox 152 / 2026-06），Nightly 默认开，已列入 Interop 2026 |

全球支持率约 82.6%（caniuse）。**不认识 `animation-timeline` 的浏览器会直接忽略它**——这意味着如果初始状态写成 `opacity: 0`，Firefox 用户看到的是**内容永久消失**，不是"动画没播"。这是这条路径唯一的真事故，也是必须渐进增强的原因。

强制写法：默认状态写成**已揭示的终态**，动画部分包进 `@supports`：

```css
.reveal {                      /* 默认 = 终态，任何浏览器都能看到内容 */
  opacity: 1;
  transform: translateY(0);
}

@supports (animation-timeline: view()) {
  .reveal {
    animation: reveal linear both;
    animation-timeline: view();
    animation-range: entry 0% entry 100%;
  }
}
```

**判据**：任何 scroll-driven 动画，把 `animation-timeline` 整行删掉之后，页面内容必须仍然完整可读。做不到就是写错了。

滚动动效同样只动 `transform` / `opacity`。视差禁止用 `background-position` 或 `top` 实现。

`will-change: transform` 只挂在真正长时间运动的层上，别整页撒，也不要预防性添加。

## 2. 视差（Parallax）

- **层数 ≤ 3**（背景 / 中景 / 前景）。多于三层时每层幅度必须继续压缩，否则画面散掉。
- **位移幅度按层递减**，背景最慢。推荐默认：前景 0（正常滚动）、中景 视口高度的 4–8%、背景 8–15%。*（推荐值，无外部来源）*
- **禁止反向视差**用在正文阅读区。反方向移动是眩晕投诉的主要来源，只允许出现在纯视觉首屏。
- **正文页只允许极轻视差**，或干脆不用。速度差的作用是暗示深度，不是表演。
- **移动端默认减弱到桌面的一半或关闭**。小屏上同样的 px 位移感知更强。
- 各层必须始终对齐成一幅完整画面，不能在滚动中途露出错位边缘。

**Hunt for**：`background-attachment: fixed`（性能差且 iOS 行为不一致）、视差层用 `top`/`margin-top` 驱动、四层以上、正文段落套在视差层里。

## 3. Sticky 滚动叙事（Scrollytelling）

固定一块区域、旁边内容继续推进，是产品拆解和数据故事的主力形态。它最大的失败模式是**用户以为页面卡死**。

- **锁定长度用滚动距离表达，不是时间**。推荐上限：整段锁定不超过 3–4 个视口高度，且至少切分成 3 段。*（推荐值，无外部来源）*
- **每一段必须有可见变化**。连续两个视口高度画面不变 = 用户会开始怀疑页面坏了，要么合并段落，要么加中间状态。
- **锁定期间必须有位置反馈**：章节编号、进度条或步骤高亮。没有进度指示的长 sticky 段不予通过。
- **释放要干净**：最后一段结束后立即恢复正常滚动，不要留一段"还锁着但什么都不变"的尾巴。
- **`position: sticky` 会被任意祖先的 `overflow: hidden/auto/scroll` 静默杀死**。改动 sticky 区块后核一遍祖先链。

**Hunt for**：sticky 容器高度写死 px 而非 vh 倍数、段落数 < 3 的长锁定、锁定区内没有任何进度指示、祖先链上的 `overflow-x: hidden`。

## 4. 滚动吸附（Scroll snap）

- **`mandatory` 只用于内容高度确定小于视口的全屏章节**。内容高于视口时用 `mandatory` 会让用户永远滚不到该屏底部——这是 snap 最常见的事故。
- **正文长内容一律 `proximity` 或不用**。强制整屏吸附会让用户无法停在想读的位置。
- **横向卡片画廊用 `proximity` + `scroll-snap-align: center`**，保留自由滑动手感。
- 需要防止一次滑动跨过多张卡片时才加 `scroll-snap-stop: always`，默认不加。
- snap 不能表现为突然跳变；吸附过程要有可感知的过渡。

**Hunt for**：`scroll-snap-type: y mandatory` 出现在包含长文的容器上、snap 容器内子项高度超过 100vh、snap 与 `scroll-behavior: smooth` 叠加导致的双重动画。

## 5. 滚动缩放与图片序列

**Scroll zoom**
- **文字不跟随大幅缩放**。文字栅格化后再放大会糊，`transform: scale()` 尤其明显。缩放交给图片或主物体，标题单独保持清晰稳定。
- 缩放必须可逆：反向滚动按原路径缩回。

**Image sequence**
- 用 `canvas` 逐帧绘制，**不要靠切换 `<img src>`**——后者会产生请求抖动和白闪。
- 帧必须**预加载**，加载完成前显示一张静态主图；加载失败也落到这张图。
- 移动端减帧（推荐：桌面帧数的 1/2 到 1/3）并考虑直接降级成静态图。*（推荐值，无外部来源）*
- 整组帧的总字节量要进性能预算——这是这类效果最容易失控的地方。

**Hunt for**：标题挂在缩放层里、`<img>` 逐帧切换、没有静态降级图、帧序列无预加载。

## 6. 横向滚动（Horizontal scroll）

- **手机端默认恢复纵向列表**。横向滑动与系统边缘返回手势冲突，且触屏横滚的可发现性差。
- **键盘可达性不能丢**：横向区块内的链接和按钮必须能 Tab 到，且聚焦时容器要自动滚到该元素。这是横向滚动最常见的 a11y 事故。
- **不要无限劫持纵向滚轮**。转换纵向滚轮为横向推进的区块要有明确的开始和结束，并且进出衔接自然。
- 必须有"还有更多内容在右边"的视觉暗示（渐隐边缘、部分露出的下一张、箭头）。

**Hunt for**：横向容器内元素 `tabindex="-1"`、滚轮劫持无退出条件、移动端未降级、无溢出暗示。

## 7. 指针动效（Pointer）

- **全部指针动效必须门控在 `@media (hover: hover) and (pointer: fine)` 内**。
- **磁吸按钮一页最多 1–2 个**，只给首要行动按钮。每个按钮都磁吸会让整个界面显得不稳定。
- **指针跟随类效果用 spring 插值，不要把值直接绑到指针坐标**（直绑没有惯性，感觉是假的）。
- **自定义光标不能让系统光标消失或变迟钝**。跟随元素可以延迟，真实指针必须始终可定位。输入框内恢复系统光标。
- **光标聚光灯 / 指针响应背景不进正文区**。持续的亮度变化干扰阅读。
- **光标拖尾经过按钮、输入框和正文时暂停**，避免遮挡点击目标。

**Hunt for**：未门控的 `pointermove` 监听、`cursor: none` 且无替代、正文容器上挂聚光灯、拖尾粒子无上限。

## 8. 多输入方式的功能等价（硬性）

这一条不是审美，是可用性底线。**`@media (hover: hover)` 门控解决的是"触屏别误触发 hover 动效"，不解决"触屏用户能不能完成同一件事"。** 这是两件事。

任何功能都必须在鼠标、触屏、键盘三种输入下都有入口：

| 桌面交互 | 必须同时提供 |
| --- | --- |
| 鼠标悬停展开 | 键盘聚焦展开 + 触屏点击展开 |
| 拖拽排序 | 上移 / 下移按钮 |
| 左右滑动切换 | 上一项 / 下一项按钮 |
| 长按打开菜单 | 可见的更多操作按钮 |
| 光标跟随类提示 | 触屏端的静态等价物或直接省略 |

**关键操作绝不能只存在于 hover 之后。** 装饰性指针效果在触屏端可以直接不渲染，功能性的必须有替代入口。

键盘那一半的常见解是 hover-only 次要操作用 `opacity-0 group-hover:opacity-100 focus-within:opacity-100` 双触发；本表补的是触屏那一半。

## 9. Reduced motion 下的降级

`prefers-reduced-motion: reduce` 时，滚动动效的降级不是全部关掉，是**换成安静版本**：

| 效果 | 降级到 |
| --- | --- |
| 视差、多层视差 | 静态，各层不位移 |
| 滚动缩放 | 直接显示终态尺寸 |
| 图片序列 | 静态主图 |
| 光标跟随、拖尾、聚光灯 | 全部关闭 |
| 自动轮播、循环动画 | 停止，显示最终状态 |
| 横向滚动叙事 | 改为纵向列表 |
| 进入视口淡入 | **保留**（短促淡化不致眩晕） |
| 滚动进度指示 | **保留**（这是位置反馈，不是装饰） |
| 加载 / 成功 / 错误反馈 | **保留**（功能性反馈不能砍） |

判据：**位移和缩放砍掉，透明度和颜色保留，所有状态反馈保留。** 降级后的页面必须仍然能看懂发生了什么。

## 10. 确定性检查候选

以下是可以 grep 的反模式，适合并入项目的静态检查：

- `background-attachment:\s*fixed`
- `scroll-snap-type:\s*[xy]\s+mandatory` 且同容器内有长文标记
- `cursor:\s*none` 且无 `@media (hover: hover)` 门控
- `pointermove` / `mousemove` 监听未包在 hover 门控内
- sticky 区块的祖先链上有 `overflow-x: hidden`（已有）
- 有 `animation-timeline` 但无 `prefers-reduced-motion` 块
- 逐帧 `<img>` 序列（连续编号 src）

反向验证要求：每条新检查上线前，必须故意造一次该检查本应捕获的失败，贴出它变红的实际输出，还原后再贴一次通过的输出。
