# 安全审查：scripts/seed.ts

## 1. 清单逐条核对

| 清单项 | 是否触及 | 说明 |
|---|---|---|
| 无密钥/token 在暂存区 | 部分触及 | `admin123` 不是真实密钥/第三方 token，是应用层字面量密码，归入下面 ④ 讨论，不判定为"密钥泄露"类问题 |
| 无新增 OWASP Top 10 漏洞 | **触及** | 疑似明文密码入库（A02 加密失败）+ 硬编码弱凭据（A07 身份鉴别失败 / CWE-798） |
| appsec 面对照 | 命中 **④ 加密·口令存储** | 触发原因：代码直接向用户表写入 `password` 字段。①③⑤ 面均不适用（无外部不可信输入、无下游注入 sink、无 HTTP/CORS 语境），按跳过条件可跳过 |

按 ④ 面对照 OWASP Password Storage Cheat Sheet 要点：
- 密码应使用强自适应哈希（bcrypt/argon2/scrypt）后存储 —— 本文件看不到任何 hash 调用，**不满足**（需确认 ORM 层是否有隐式 hook）
- 不应为特权账号（role: admin）使用弱/可猜测的固定默认密码 —— **不满足**

## 2. 审查结论

**F1 — 硬编码弱管理员密码 `admin123`（CWE-798）**
- 严重度：**MEDIUM**
- 是否要求修改：**是**
- 理由：即便定位为"本地开发种子脚本"，固定弱密码 + `role: 'admin'` 的组合是经典后门模式。一旦此脚本被复制/误跑到非纯本地环境（如 `DATABASE_URL` 误配到共享/预发库，这在团队协作中并不罕见），会产生一个已知凭据的管理员账号。建议改为从环境变量读取，缺省时随机生成并仅打印一次，而不是写死字面量。

**F2 — 密码疑似明文入库，未见哈希处理**
- 严重度：**HIGH（待确认后可能降级）**
- 是否要求修改：**是，或需作者书面确认**
- 理由：`db.user.create` 直接把明文字符串写入 `password` 字段，本文件范围内看不到 bcrypt/argon2 等哈希调用。两种可能，都需要处理：
  1. 若 Prisma/db 层没有自动 hash 的 middleware/hook → 这是真实的明文密码持久化，违反 OWASP Password Storage Cheat Sheet 核心要求；
  2. 若 db 层确实有 hash hook（此文件外定义）→ 那么风险降级为 INFO，但请在 PR 描述或注释中明示该假设，避免后续读者误以为这里是明文写入而重复踩坑，或误以为登录校验也接受明文。
- 要求：请指出/链接 hash 发生的位置；若确实没有，需在写入前显式 `await bcrypt.hash(...)`。

**F3 — 缺少环境守卫，无法防止误跑到非本地库**
- 严重度：**LOW**
- 是否要求修改：建议但不阻塞
- 理由：脚本没有基于 `NODE_ENV` 或 `DATABASE_URL` 的保护，无法防止被误执行于共享环境。建议加一层守卫（例如非 `development`/非 localhost 时 throw）。

**F4 — `role: 'admin'` 硬编码**
- 严重度：**INFO**
- 是否要求修改：否
- 理由：种子脚本创建管理员账号是预期行为，本身不是漏洞，只是与 F1/F2 叠加时放大整体风险，已在上面一并说明。

## 3. 安全自述

本次审查应用了三项检查：密钥暂存区扫描、OWASP Top 10 新增风险扫描、以及 appsec 五面命中判定。五面判定命中「④ 加密·口令存储」（代码直接写用户密码字段），因此额外对照 OWASP Password Storage Cheat Sheet 的核心要求（强哈希算法、禁止明文存储、禁止弱默认凭据）逐条检查；①不可信输入 ③输出注入 ⑤CSRF/CORS 三面因本文件既无外部输入来源、也无下游注入 sink / HTTP 语境，按清单跳过条件判定为不适用，未展开对照。

对硬编码字面量 `admin123` 的定级：没有当作"密钥泄露"处理（它不是接入第三方服务的真实凭据，不属于需要立即吊销轮换的 secret），而是按 CWE-798（硬编码凭据）+ 弱密码两个角度定为 MEDIUM——理由是它的实际杀伤力依赖于误用场景（脚本被跑到非本地环境），本身在纯本地开发闭环里风险有限，但一旦环境假设被打破后果是获得管理员权限，因此不能定为 LOW/INFO，也未到需要立即阻断合并的 CRITICAL。密码是否明文入库（F2）判定为待确认项而非直接坐实 HIGH，是因为哈希逻辑可能存在于本文件之外（ORM hook），仅凭本文件不能排除；按"证据不足时不夸大也不轻放"的原则，标记为需要作者确认的 HIGH，而不是直接拍板 CRITICAL 或悄悄放过。
