## 新增/修改文件

**`migrations/0002_create_users.sql`** — `users` 表（email 唯一、password_hash/salt/iterations）

**`src/lib/password.ts`** — PBKDF2-SHA256 口令哈希（Workers Web Crypto 唯一内建选项），120,000 次迭代，常数时间比较防时序旁道

**`src/lib/session.ts`** — session 用 32 字节随机 token 作为 KV 的不透明 key（`session:{id}` → `{userId, email, createdAt}`），`expirationTtl` 24h 自动过期；`requireSession()` 供受保护接口复用

**`src/lib/rateLimit.ts`** — 按邮箱维度的登录失败锁定（5 次失败锁 15 分钟），复用 SESSIONS 这个 KV

**`src/lib/csrf.ts`** — 从 `comments.ts` 抽出的同源校验（Origin/Referer），三个状态变更接口共用

**API 路由**（`src/pages/api/`）：
- `register.ts` — POST，建号用（演示/测试账号，非最终产品级注册流程）
- `login.ts` — POST，校验邮箱+口令，成功后 `cookies.set('session_id', ..., {httpOnly, secure, sameSite:'lax', path:'/', maxAge:86400})`
- `logout.ts` — POST，销毁 KV 里的 session 并清 cookie
- `me.ts` — **受保护接口**，GET，无有效 session 直接 401

**`wrangler.toml` / `src/env.d.ts` / `package.json`** — 新增 `SESSIONS` KV 绑定占位符（`REPLACE_WITH_YOUR_KV_NAMESPACE_ID`，非真实值）+ 对应迁移脚本

## 应用了哪些安全检查（自述）

- **A02 加密失败**：口令用 PBKDF2-SHA256 + 每用户随机 salt 存储，不明文/不可逆存储；哈希比较用常数时间异或，防时序旁道泄露正确前缀。
- **A03 注入**：D1 全部走 `.bind()` 参数化查询，无字符串拼接 SQL。
- **A07 身份鉴别失败**：登录失败与用户不存在返回同一句模糊错误（"邮箱或密码错误"），且用户不存在时仍执行一次等成本的哈希运算，防止靠响应时间/内容枚举已注册邮箱；按邮箱加了失败锁定限流防撞库。
- **A01 访问控制**：`/api/me` 严格校验 session 是否存在于 KV 且未过期，否则 401；session 是服务端 KV 查找的不透明随机 token，客户端无法伪造或篡改。
- **Cookie 安全**：`HttpOnly`（防 XSS 窃取）+`Secure`（仅 HTTPS 传输）+`SameSite=Lax`（降低 CSRF 风险）+ 显式 `Max-Age`（限制会话生命周期，配合 KV TTL 双重过期）。
- **CSRF**：三个状态变更接口（register/login/logout）都做了同源校验，和原有 `comments.ts` 保持一致的防护策略。
- **输入校验/资源耗尽防护**：邮箱正则+长度上限、密码长度上下限，避免超长输入被喂进 PBKDF2 / 存储层。
- **信息泄露**：所有异常路径只返回中文提示，不透出堆栈或内部错误细节。
