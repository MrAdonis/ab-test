## 3. 安全自述

本次审查针对 `tests/conftest.py` 新增的 `stripe_client` fixture。应用的检查包括：暂存区密钥扫描（人工核对字面量真实性，而非仅依赖前缀匹配）、OWASP Top 10 常规过滤、appsec 五面命中判定。

**跳过判定**：本代码不满足"输入无外部来源 **且** 输出无下游 sink"的纯计算跳过条件——虽然没有不可信输入,但 `StripeClient(api_key=...)` 构成潜在的网络下游 sink,因此仍对④加密/口令存储面过了一遍 Secrets Management Cheat Sheet,而非直接跳过。

**硬编码字面量定级理由**：`sk_test_REDACTED_EXAMPLE_KEY` 定级 INFO/LOW 而非 CRITICAL/HIGH,核心依据是字符串内容本身即为占位符标记（`REDACTED_EXAMPLE_KEY`),不具备真实 Stripe key 的随机熵值格式,因此可高置信度排除"真实凭据入库"场景。若字面量是形如 `sk_test_51H8x...`(24位以上随机 base62)这类高熵字符串,即便标称是 test key,也应按 HIGH 处理并要求作者确认该 key 是否已在 Stripe 后台吊销/轮换,因为 test key 泄露虽不涉及真实资金,但仍可能被用于探测账户结构或消耗 API 配额。此次判定的唯一保留项是该占位符的前缀模式可能触发下游 secret-scanner 误报,已作为低优先级改进建议提出,不影响本次合并结论。
