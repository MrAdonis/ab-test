## 核心工作流

### Step 0：方向门（强制，60 秒内完成）

收到素材后，**先出方向稿，不直接生成完整 deck**。

从用户提供的素材中提取三个决策点，一次性询问：

```
基于你的素材，我准备这样做：

1. 风格基调：[商务极简 / 技术讲台 / 品牌发布 / 内部工作坊]——推荐「X」，因为 Y
2. 布局密度：[重图轻文（演讲主导）/ 文字平衡（自述 PPT）/ 数据密集（汇报）]——推荐「X」
3. 配色方向：[单色系 + 强调色 / 双色对比 / 品牌色（请提供）]——推荐「X」

确认或修改后我开始生成。
```

**不能自动判断跳过此步**——即使素材已含明显线索（如"investor pitch"），也要把推断结论写出来让用户确认，不静默进入 Step 1。

---

### Step 1：生成首页 + 样本页（先出，等确认）

方向确认后，**只生成两页**：

- **首页**（封面）：标题、副标题、演讲者/场景标注
- **第 2 页**（内容样本）：一个典型内容页，含真实标题 + 内容结构（不用占位文字）

输出格式为完整可渲染的 HTML（`<html>…</html>`），两页在同一文件里，用固定分页符分隔（`<div class="slide">`）。

在 HTML 之后紧跟一行判断：

```
样本页已出。确认风格继续生成剩余页，或说「调整：[具体反馈]」。
```

**风格规则（首页 + 样本页均适用）**：

| 维度 | 规则 | 依据 |
|------|------|------|
| 留白 | ≥ 30% 空白面积 | Calimari Rule：低信息密度感知档次更高 |
| 主色 | ≤ 2 色 + 1 强调色 | Cleveland & McGill 1984：颜色识别上限 5-7，演示场景更严 |
| 文字对比 | 正文对背景对比度 ≥ 7:1 | WCAG AAA，投影仪打折后仍可读 |
| 字重层级 | ≤ 3 级（大标题 / 次标题 / 正文） | Tufte：层级越多数据墨水比越低 |
| 单页文字量 | 正文字数 ≤ 60 字 / 页 | 演讲稿场景：听众看屏幕不读屏幕 |
| 字体 | system-ui 或 Google Fonts 单一字族 | 确保无字体缺失黑框，投影渲染稳定 |

**无法量化，保留文字判断**：视觉重心落在内容核心而非装饰元素上；配色在整个 deck 里叙事统一，不因页面内容不同而漂移。

---

### Step 2：生成完整 deck

样本页确认后，按以下顺序生成剩余页：

1. 读取用户原始素材，提取页面骨架（每页：标题 + 核心主张 + 支撑内容）
2. 严格复用 Step 1 确认的样式变量（颜色、字体、间距），不重新决定
3. 特殊页型（封底、过渡页、数据图表页）在生成前用一行注释声明：`<!-- 过渡页：进入第二章节 -->`
4. 输出单一 HTML 文件，每页 `<div class="slide" id="slide-N">`

**数据图表页（如有）的额外规则**：

```
# Good — 单图表单主张，图表类型与数据关系匹配
<div class="slide">
  <h2>增长来自复购，不是新客</h2>
  <div class="chart"><!-- 堆叠柱状图：新客 vs 复购拆分 --></div>
  <p class="takeaway">复购占比 Q4 达 68%</p>
</div>

# Bad — 多图堆一页，主张藏在图里
<div class="slide">
  <div class="charts-grid"><!-- 4 个图表 --></div>
</div>
```

图表用 SVG 内联（不依赖外部 JS 库），颜色严格从 Step 1 配色中取，不引入新色。

---

### Step 3：交付与验证

生成完毕后，输出三行验收清单，要求用户逐项确认：

```
- [ ] 在浏览器打开后每页均可渲染（无乱码、无黑框）
- [ ] 全文配色与样本页一致，无新增颜色
- [ ] 页数与素材章节数吻合（共 N 页）
```

**自我排除（以下场景不走本流程）**：

- 用户已提供完整设计稿（.fig / .psd）→ 直接出代码实现，跳过 Step 0-1
- 需要动效、视频嵌入、Presenter Notes → 告知本 skill 不支持，建议用 Reveal.js 模板
- 页数 ≥ 30 页 → 先出前 10 页确认后分批生成，不一次性输出（单次 HTML > 800 行会超出可靠渲染范围）
