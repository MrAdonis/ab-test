# t37 场景 — 生成型 skill「先锁方向，再昂贵生成」模式验证

来源：Zara Zhang frontend-slides walkthrough（youtube 372Iksaz8b0，22k★，"我们能学到什么"）。
方法：Sonnet 隔离子代理生成 A（基线 = 现有 skill-design-patterns 全文）/ B（基线 + 注入模式）输出，Sonnet 盲评委 5 维打分，位置每场景翻转。B>A 才落地 live config，否则回滚 + 记 rejected buffer。

## S1-deck（生成型 = 多页 HTML 幻灯片）
> 写一个「把用户提供的素材生成多页 HTML 幻灯片」skill 的「核心工作流」段（写流程正文，不写 frontmatter）。
> 用户对品质的表述："生成的 deck 要好看、贴合我的演讲场景，别让我等它做完一整版才发现整个风格不对、又得重来。"
> 你要把这个目标转成 agent 可执行的核心工作流。

## S2-poster（生成型 = 品牌主视觉海报 KV）
> 写一个「根据品牌信息生成主视觉海报（KV）」skill 的「核心工作流」段（只写流程正文）。
> 用户表述："海报要高级、符合品牌调性，别一上来生成一堆我不要的方向白白浪费时间和额度。"
> 你要把这个目标转成 agent 可执行的核心工作流。

## 评分（每场景满分 50，5 维 × 10）

1. **防跑偏**：在昂贵生成前是否有锁定方向的机制（问意图 / 探风格），避免整版做错才发现
2. **经济性**：是否用廉价产物先验证方向（预览 / 选项 / 草稿），而非直接 build 全量
3. **可执行性**：流程是具体动作（问哪几项、先出几个什么），不是"按需判断 / 酌情沟通"
4. **自由度匹配**：没给简单/廉价步骤套过度问答仪式；锁方向的闸只用在该用的地方，不堆冗余流程
5. **简洁密度**：段落紧凑、信息密度高，没有套话填充
