# S1 场景：「把用户素材生成多页 HTML 幻灯片」skill 的核心工作流段

## 方案 甲

## 核心工作流

### Step 0：方向门（强制，60 秒内完成）

收到素材后，**先出方向稿，不直接生成完整 deck**。

从用户提供的素材中提取三个决策点，一次性询问：

```
基于你的素材，我准备这样做：

1. 风格基调：[商务极简 / 技术讲台 / 品牌发布 / 内部工作坊]——推荐「X」，因为 Y
2. 布局密度：[重图轻文（演讲主导）/ 文字平衡（自述 PPT）/ 数据密集（汇报）]——推荐「X」
3. 配色方向：[单色系 + 强调色 / 双色对比 / 品牌色（请提供）]——推荐「X」

确认或修改后我开始生成。
```

**不能自动判断跳过此步**——即使素材已含明显线索（如"investor pitch"），也要把推断结论写出来让用户确认，不静默进入 Step 1。

---

### Step 1：生成首页 + 样本页（先出，等确认）

方向确认后，**只生成两页**：

- **首页**（封面）：标题、副标题、演讲者/场景标注
- **第 2 页**（内容样本）：一个典型内容页，含真实标题 + 内容结构（不用占位文字）

输出格式为完整可渲染的 HTML（`<html>…</html>`），两页在同一文件里，用固定分页符分隔（`<div class="slide">`）。

在 HTML 之后紧跟一行判断：

```
样本页已出。确认风格继续生成剩余页，或说「调整：[具体反馈]」。
```

**风格规则（首页 + 样本页均适用）**：

| 维度 | 规则 | 依据 |
|------|------|------|
| 留白 | ≥ 30% 空白面积 | Calimari Rule：低信息密度感知档次更高 |
| 主色 | ≤ 2 色 + 1 强调色 | Cleveland & McGill 1984：颜色识别上限 5-7，演示场景更严 |
| 文字对比 | 正文对背景对比度 ≥ 7:1 | WCAG AAA，投影仪打折后仍可读 |
| 字重层级 | ≤ 3 级（大标题 / 次标题 / 正文） | Tufte：层级越多数据墨水比越低 |
| 单页文字量 | 正文字数 ≤ 60 字 / 页 | 演讲稿场景：听众看屏幕不读屏幕 |
| 字体 | system-ui 或 Google Fonts 单一字族 | 确保无字体缺失黑框，投影渲染稳定 |

**无法量化，保留文字判断**：视觉重心落在内容核心而非装饰元素上；配色在整个 deck 里叙事统一，不因页面内容不同而漂移。

---

### Step 2：生成完整 deck

样本页确认后，按以下顺序生成剩余页：

1. 读取用户原始素材，提取页面骨架（每页：标题 + 核心主张 + 支撑内容）
2. 严格复用 Step 1 确认的样式变量（颜色、字体、间距），不重新决定
3. 特殊页型（封底、过渡页、数据图表页）在生成前用一行注释声明：`<!-- 过渡页：进入第二章节 -->`
4. 输出单一 HTML 文件，每页 `<div class="slide" id="slide-N">`

**数据图表页（如有）的额外规则**：

```
# Good — 单图表单主张，图表类型与数据关系匹配
<div class="slide">
  <h2>增长来自复购，不是新客</h2>
  <div class="chart"><!-- 堆叠柱状图：新客 vs 复购拆分 --></div>
  <p class="takeaway">复购占比 Q4 达 68%</p>
</div>

# Bad — 多图堆一页，主张藏在图里
<div class="slide">
  <div class="charts-grid"><!-- 4 个图表 --></div>
</div>
```

图表用 SVG 内联（不依赖外部 JS 库），颜色严格从 Step 1 配色中取，不引入新色。

---

### Step 3：交付与验证

生成完毕后，输出三行验收清单，要求用户逐项确认：

```
- [ ] 在浏览器打开后每页均可渲染（无乱码、无黑框）
- [ ] 全文配色与样本页一致，无新增颜色
- [ ] 页数与素材章节数吻合（共 N 页）
```

**自我排除（以下场景不走本流程）**：

- 用户已提供完整设计稿（.fig / .psd）→ 直接出代码实现，跳过 Step 0-1
- 需要动效、视频嵌入、Presenter Notes → 告知本 skill 不支持，建议用 Reveal.js 模板
- 页数 ≥ 30 页 → 先出前 10 页确认后分批生成，不一次性输出（单次 HTML > 800 行会超出可靠渲染范围）

## 方案 乙

## 核心工作流

### 闸 1：意图锁定（生成前必问，不可跳过）

收到 deck 请求后，**先问完以下四项再动手**，不拿模糊需求直接生成。四问固定清单，agent 每次问全，不做"看情况省略"的判断：

1. **用途**：keynote 现场演讲 / 发给对方自读 / 内部 review？（决定文字密度和视觉比重）
2. **页数预期**：大约多少页？有硬上限吗？
3. **受众**：谁在看——技术 / 业务 / 投资人 / 混合？他们的背景前置知识是？
4. **密度偏好**：speaker-led（每页一句话，演讲者补充细节）还是 read-first（页面自说明，不依赖演讲者）？

用户已在 prompt 里写死全部四项则跳过询问，直接进闸 2。

---

### 闸 2：廉价方向样本（锁定风格，才 build 全量）

四问答完后，**先生成 3 个封面方向**，不生成完整 deck。每个方向输出：
- 封面页完整 HTML（标题 + 副标题 + 视觉风格，100% 可渲染）
- 一句话描述该风格的核心主张（如"深色底 + 大字留白，适合现场演讲强调感"）

用户从三个方向选一个（或说"更偏向 A 但换个配色"），方向锁定后才进入第三步。

**方向样本的视觉约束**（可测阈值，带依据）：

- 留白 ≥ 35%（Calimari Rule：信息密度越低，感知档次越高）
- 主色 ≤ 2，背景+前景对比度 ≥ 7:1（WCAG AAA）
- 字重层级 ≤ 3 级（标题 / 次级标题 / 正文），每级字号差 ≥ 4px
- 单封面不超过 12 个词（排除公司/主题名）

[无法量化，保留文字] 三个方向之间必须有明显的风格差异——不是"同一个模板换配色"，是排版逻辑不同（极简大字 / 数据卡片式 / 图文各半），让用户有真实选择。

---

### 第三步：全量 build（按锁定方向）

方向确认后，按以下顺序生成完整 deck：

**结构阶段（先给大纲，等确认）**

生成 1 份页面大纲（每页：页码 + 标题 + 核心内容一句话描述），不写 HTML。用户对大纲有异议时现在改，比改完 HTML 再改成本低一个数量级。用户确认大纲后才写 HTML。

**生成阶段（整套 HTML）**

按锁定风格逐页生成，每页 HTML 独立可渲染（不依赖上一页的变量）。技术约束：

- 单文件输出，CSS inline 或 `<style>` 内嵌，不引用外部资源（字体用 Google Fonts CDN 或系统字体栈，网络不可用时有 fallback）
- 每页 `.slide` 固定 1280×720px，支持 `?page=N` 单页访问
- 导航：键盘左右键翻页 + 页码指示器
- 字体最小不低于 18px（演讲场景后排可读，来自演讲标准实践）

**内容填充规则**（按密度偏好分支）：

| 密度偏好 | 每页文字量 | 图表 |
|---------|-----------|------|
| speaker-led | 标题 + ≤ 3 个要点，每点 ≤ 10 字 | 大图 / 数字 hero，无小字注释 |
| read-first | 标题 + 正文段落，≤ 100 字/页 | 图表带轴标签和数据标注 |

---

### 第四步：交付与自检

生成完成后，agent 对照以下清单自检，不通过的直接修完再给用户：

- [ ] 所有页面单独打开可渲染（无 JS 报错，无空白页）
- [ ] 封面风格与用户选定方向一致，后续页面配色/字体无漂移
- [ ] 页数在用户要求范围内（±2 页可接受）
- [ ] speaker-led 模式下每页文字量不超标；read-first 模式下图表有标注
- [ ] 最后一页有明确收场（行动号召 / 联系方式 / Q&A 占位），不以内容页结束

自检通过后输出 HTML 文件路径，并说明：哪一页是结构上最脆弱的（最密 / 最依赖演讲者解释），供用户重点 review。

---

### 跳过条件

以下情况跳过对应的闸，不强制走完整流程：

- 用户 prompt 已含完整四问答案 → 跳过闸 1
- 用户说"直接做，我接受任何风格" → 跳过闸 2，记录"风格由 agent 自主选择"
- 页数 ≤ 5 页（廉价，先探方向的经济价值低）→ 跳过闸 2，直接生成，完成后提示"如不满意风格可要求重做"
