## 模式：生成型 skill 先锁方向，再昂贵生成

生成型/品味驱动的 skill（产出幻灯片、海报、落地页、长文这类**昂贵且方向主观**的东西），最大的浪费不是单步做错，是**整个产物往用户不要的方向 build 完了才发现**——白烧 token、白等时间。两道闸前置防这个：

**闸 1 — 生成前榨取意图（向用户问死几个固定问题）**：生成型 skill 在产出前，先用**固定的几个问题**把用户意图锁定，不拿模糊需求直接开生成。模型缺 context 就产 slop。问题**枚举成固定清单**（用途 / 篇幅 / 受众 / 密度），不是"看情况问"——固定清单 agent 每次问全，自由判断会漏。

**闸 2 — 昂贵生成前先放廉价预览**：build 全量产物前，先生成**廉价的方向样本**（3 个封面方向 / 3 个排版骨架 / 1 段示例），让用户选定方向，锁定后才 build 整套。模型往错风格跑一次的代价，在"生成 30 页"和"生成 3 个缩略"之间差一个数量级——先用便宜的探方向，贵的只做一次。

**为什么是生成型专属**：确定性 skill（API 调用、文件转换、数据抓取）输出唯一正确，没有"方向"可锁，套问答闸纯属仪式。这两道闸只对"输出主观 + 生成昂贵 + 跑错方向要重来"三重条件成立。

**Good vs Bad**：
```
# Bad — 拿模糊需求直接 build 全量
用户："做一份产品发布会的 deck"
→ skill 直接生成 30 页完整 deck → 风格不对 → 全部重来

# Good — 先锁方向再 build
用户："做一份产品发布会的 deck"
→ skill 先问：用途 / 篇幅 / 受众 / 密度（speaker-led or read-first）
→ 生成 3 个封面方向缩略，用户选 → 按选定风格 build 全 30 页（只 build 一次）
```

**跳过条件**：① 确定性 skill（无主观方向）；② 单步廉价生成（一张图、一段话——本身就廉价，没有"先探方向"的经济价值）；③ 用户已在 prompt 里给死完整 spec + 风格（方向已锁，别再多问一轮）。

> 来源：Zara Zhang frontend-slides walkthrough（youtube 372Iksaz8b0，22k★）。她的 skill 内建四问（purpose/length/content/density）+ 三封面预览闸，自述动机="model 缺 context 产 slop"和"模型老往我不喜欢的风格跑、白烧 token"。
