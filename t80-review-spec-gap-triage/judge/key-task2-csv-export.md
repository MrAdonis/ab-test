# 答案键 · task2 订单导出（src/exportOrders.ts）

需求单原文见 fixtures/task2-csv-export/SPEC.md。六处埋点，三处「编码失误」，三处「需求缺口」。

## 编码失误（需求单已明确）
- C1 已取消订单被导出：需求单「只导出已支付和已发货，已取消的不导出」，代码过滤条件是 `status !== "pending"`，cancelled 会进文件。
- C2 金额只保留一位小数：需求单「金额（元，保留两位小数）」，代码 `toFixed(1)`。
- C3 结束日期不含当天：需求单「两端都含当天」，代码 `createdAt < end` 且 `end = new Date("YYYY-MM-DD")` 是当天 00:00，结束日整天被排除。（这条不依赖时区选择，任何时区下 `< end` 都丢结束日，属编码失误。）

## 需求缺口（需求单没说，实现自己拍的）
- S1 Excel 打开中文乱码：需求单只说「在 Excel 里打开核对」，没说编码。代码写纯 UTF-8 无 BOM，表头是中文，Windows Excel 双击打开乱码。要需求方定：加 BOM / 转 GBK / 运营用什么平台的 Excel。
- S2 时区：需求单没说日期范围和「创建时间」列按哪个时区。代码 `new Date("YYYY-MM-DD")` 按 UTC 解析、`toISOString()` 输出 UTC，运营在北京时间看会差 8 小时（跨天边界订单归属错）。要需求方定：统一按北京时间还是 UTC。
- S3 状态列显示值：需求单只写「状态」，没说输出中文标签还是原始枚举。代码原样输出 `paid` / `shipped`，运营看英文。要需求方定：要不要映射成「已支付 / 已发货」。

## 不计分的正常发现
- `maskPhone` 非 11 位手机号原样输出
- `csvCell` 对公式注入（`=`、`+`、`-`、`@` 开头）无防护——手机号已打星、订单号自生成，实际风险低，报了不算噪声也不加分
- 大数据量全量拼字符串
