## 逐维评分

| 维度 | 甲 | 乙 |
|---|---|---|
| 1 终止判断 | 3 | 6 |
| 2 每一问的边际价值 | 5 | 7 |
| 3 收口质量 | 3 | 9 |
| 4 推进可见度 | 4 | 8 |
| 5 专业质量 | 7 | 8 |
| 6 用户体感 | 3 | 7 |

## 1. 终止判断

甲在用户连续答不出后毫无调整。「Nginx 是否记录参数」→「没想过」，「前端是否分页」→「没具体看过」，「课表多久变一次」→「没想过」，「健身房 IP」→「不知道」，「有没有对接人联系方式」→「没想过」，「UA 长什么样」→「还没看过」——六连空，且最后三问全部指向同一个用户已经说过两次「还没扒 access log」的对象。整段没有一次识别到信息井已经干了，是被「我们今天时间就到这里了」掐停的，且掐停时手上零决策。

乙也没自己收尾，但中途两次明确识别耗尽并换轨：「这是你已经答不上来的第三个『需要翻日志才知道』的问题,继续在这条分支上问不会有新信息」「数据侧到这里已经掏空…转向一个不依赖日志、现在就能回答的问题」。换轨之后连拿三个实答（单机 4C8G / MySQL 同机 / 无 Redis；已是真实生产故障；同意先上粗闸）。扣分处：Q6–Q9 四连空才开始换轨，本可更早；以及拿到「现在就上粗闸」这个决策后仍多问了一轮，本可就地收尾。

## 2. 每一问的边际价值

甲最好的两问都很硬：慢查询/索引那问（阈值松紧确实取决于单次查询成本）和「除普通用户外还有没有其他合法调用方」——后者直接挖出健身房脚本，是全场信息增量最大的一问。但同一段里有三次纯催工：「数据库那边有结果了吗？」「数据库那边先放一放」「数据库是不是有慢查询,你那边跑得怎么样了?」，零信息。还有明知不可答的：「有没有对方任何一个联系人…方便你今天就发消息问」，用户只能回「得回去翻翻当时的沟通记录」。

乙几乎每问都自带「答案不同则结论不同」的说明，且真的成立（无 user_id → 排除按用户限流；无固定出口 IP → 排除白名单；单机无 Redis → 排除共享状态的实现分支；已是故障 → 决定要不要等日志）。扣分处：Q3 问过 IP 分布得到空答后，Q8 又以「随手翻个几十条眼扫一下」重问一遍同一对象；Q7（业务能否接受几分钟延迟）紧跟在 Q6（课表变更频率）空答之后，是同一条死枝上的追问。

## 3. 收口质量

甲的收尾就是把没问完的题重列一遍：「我把还悬着的几件事列一下」+ 五条待查 + 「等你把这些拿到,咱们接着…」。没有事实/假设分离，没有把「他问的限流」和「他真正的问题是单接口拖垮同机 MySQL」区分开，没有任何今天可执行的动作。按口径属于典型中低分。

乙给了完整交接：原问题 vs 实际要解决的问题（「这是止血问题,不是长期限流架构问题」）、已确认事实六条、纯属假设五条、以及最关键的一句——「**最可能推翻现有结论的变量**:Nginx 前面有没有 CDN/WAF…不是调阈值,是换机制」，并附带判读规则（贴出 tail 后看 remote_addr 是不是同一小撮陌生 IP，是则换方案，否则粗闸照单上线）。扣分处：开头「用户没有回收尾要求,但要点已收拢」是泄露的内部独白，而且事实说反了（用户明确要求收尾）；另有一句「真实攻击体量和你的服务器承受不住这一点比,应该是明显偏高的」语义破碎且是无据推断。

## 4. 推进可见度

甲的提问块高度模板化（每轮都是问题 + 「我的推荐判断」），但判断本身很少因上一轮回答而改写。最刺眼的是：它问到「前面有没有 CDN/WAF」并拿到了明确回答「前面没有 Cloudflare 或 WAF 这些,就是 Nginx 直接转发」——这条在乙那里被认定为最关键变量——甲拿到手后没有任何后续动作，也没进最终清单。信息进来了，理解没变。

乙每轮开头都是「明确了:X——这意味着 Y」，且方案骨架肉眼可见地收敛：按 user_id 限流被排除 → IP 白名单被排除 → 缓存挂起为默认假设 → 机制定为 Nginx `limit_req` → 时机定为现在就上。到后期读者能复述出方案长什么样。

## 5. 专业质量

两边都靠谱。甲独有一条乙完全漏掉的：单次查询成本决定阈值下限（「如果这条查询本身要 200ms+,那十几 QPS 打满数据库连接池很正常」），这条真的成立，乙全程没问索引/慢查询，它给的粗闸阈值因此缺一个依据。乙独有的是全场最锋利的一点：`remote_addr` 可能是 CDN 节点 IP 而非真实 IP，此时按 IP 限流要么全放要么全挡；以及单机/多实例决定限流状态存哪。乙略胜在这些点都被挂进了决策链，甲的好洞察大多问完就散了。

## 6. 用户体感

甲最后四问全落在用户已声明「还没看过日志」的同一块地上，用户被迫连续说「我真没想过」「我还真不知道」，然后主动喊停——是被拷打感。乙中段有一小段同样的疲劳（连续四问空），但每次卡住都给出出口：把不确定项「搁置为默认假设,不让它卡住整个方案」，把回忆不出来的事改成「不是回忆,是直接查:`tail -n 5`」，最后用户带着一个已拍板的动作离开。扣分处是「明确了:」开场的重复度高，读久了机械。

## 如果我是这位用户

选乙——同样是被信息卡住，甲让我离场时只多了一张待办清单，乙让我离场时手上有一个今晚能上的止血动作、一条会推翻它的具体变量、以及一句「贴日志出来先看哪一行」的判读规则。
