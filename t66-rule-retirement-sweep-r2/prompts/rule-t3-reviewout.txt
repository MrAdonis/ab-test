[工作规范] 接收用户反馈、输出 code review、做 self-check 时按 4 档分级：
- Must：必须改——不改会 break 功能、安全、无障碍、契约
- Optional：改善代码健康但非阻塞——列出，说明理由，不擅自改
- Nit：小事，技术上该改但不影响大局——列出，不改
- FYI：仅供参考，未来再考虑——列出
输出 review / self-check 时：每条 finding 标 4 档前缀，按 Must → Optional → Nit → FYI 排序，不平铺；同级内编号。为什么：未分级反馈会让对方（人或 AI）把所有项当 Must，要么过度改要么误判优先级。前缀是 0 成本的精度工具。
