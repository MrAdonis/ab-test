核心设计思路:

1. **完成标准有 6 条边界条件,不只是"测试全过"**——单独看"npm test 通过"这个目标是有漏洞的:删测试、加 `.skip`、改断言迁就 bug 都能让它"达标",却等于没做事。所以额外加了:测试总数不能减少、跳过标记不能变多、vitest 配置不能被改窄、`@ts-ignore`/`as any`/放宽 tsconfig 不能被用来掩盖 typecheck 报错。

2. **跨进程续接靠 `.loop/` 目录**,因为每轮都是没有记忆的全新进程:`baseline.json` 记初始基线,`progress.md` 是每轮追加的日志,`STATUS` 文件是三态开关(`CONTINUE`/`DONE`/`BLOCKED`),外层 shell 循环只需要读这一个文件就知道该不该停。

3. **止损机制**:连续 3 轮失败测试名单完全不变判定为卡住;遇到"测试和实现到底哪个对"这种需要人判断的分歧,不允许瞎猜着改测试,直接判 `BLOCKED` 并把疑点写进 `NEEDS_HUMAN.md`,留给你早上看。

4. 文件末尾附了一个最简外层循环脚本示例,方便你接上状态文件。
