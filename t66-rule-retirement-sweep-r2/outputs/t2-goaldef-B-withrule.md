已写入 `unattended-test-fix-task.md`。核心设计：

**反古德哈特的关键点**——只写"测试全过"不够，因为最便宜的达标路径是删测试/加 skip/削断言。所以完成标准是多条同时成立的边界条件：全部测试通过 + typecheck 零报错 + 用例总数不低于基线 + 测试文件集合不缩水 + git diff 里没有测试文件被删 + skip/only/todo 标记数不超基线 + `@ts-ignore`/`as any` 抑制符数不超基线。

**跨轮记忆问题**——每轮是全新进程,没有对话记忆,所以状态全部落盘：`.agent/baseline.json`(第一轮建立、之后任何一轮不许改)记录基线数字，`.agent/PROGRESS.md` 追加写审计日志，`.agent/STATUS` 是唯一的信号通道(`IN_PROGRESS`/`DONE`/`ESCALATE`)，外层循环脚本读这个文件决定要不要再拉一轮。

**卡住时不硬撑**——连续两轮失败测试集合没变化、或自检发现红线被踩、或发现测试预期本身有问题，都要求写 `ESCALATE` 停下来等人看，而不是自己删测试或回滚，也不是死循环烧一整晚 token。

这份文件没有绑定具体项目结构（我这边目录里没有你说的那个 TS 项目），用的是通用 vitest 文件名规则（`*.test.ts(x)`/`*.spec.ts(x)`），放到你项目里之前建议扫一眼第 1、5 节的 grep/glob 是否匹配你实际的测试文件命名习惯。
