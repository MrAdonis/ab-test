两份产出回应同一条请求：「把「MCP 和 Skills 的区别」写成一条 260 字以内的中文推文，读者是天天用 Claude Code 的开发者，别写成科普腔，要有自己的判断。」

请你盲评。三个维度各 10 分：① hook 强度 ② 信息密度与判断力 ③ AI 腔（越少越高分，注意 setup-reveal 两拍句式「不是X而是Y」、连续短句成段、空洞排比）。字数按汉字+英文术语计，超 260 在③扣分。

先分维度写评语并给分，最后一行按格式输出：`甲总分 X/30，乙总分 Y/30`

=== 甲 ===
MCP 是给 Claude 接外部世界的接口层,Skill 是给 Claude 灌专业操作手册的知识层——一个决定它能碰到什么,一个决定它碰到之后该怎么做。日常写代码那种"改文件、跑命令"根本不需要 MCP,Read/Edit/Bash 早就够了;真正该上 MCP 的是那些不进容器就摸不到的资源,比如活的数据库连接、企业内部 API、需要维持会话状态的第三方服务。反过来 Skill 从不装新工具,它是把你和团队踩过的坑、约定俗成的规范提前写进 context,让模型少犯当场瞎猜的错误。两个混着评估是常见误判:嫌 Claude Code 慢,先查是不是挂了一堆用不上的 MCP server 在占 context,而不是急着加更多 Skill。

=== 乙 ===
MCP 是给模型接第三方服务的协议层,负责"连什么";Skills 是给 Claude Code 加流程知识和判断力的,负责"怎么干"。前者装了就是能力扩展(多一堆 tool),后者装了是行为约束(该走哪条路、遇到什么先查什么)。混着理解最容易踩的坑:以为装个 MCP 就能替代好的 skill 编排——MCP 只负责把工具递给你,Skill 才管什么时候该用、用错了怎么办。真正的判断力活在 Skill 里,不在 MCP 里。
