# t69 · 证据 ledger 升格通用规则

**结论：KEEP**（写入 `~/.claude/rules/writing.md` MUST 段，触发收窄为「判定/筛选/归类」类产出）

## 来源

trycompai 开源 agentic CRM 的 `evidence.md` skill——工具只报「看见了什么来源」，不报自评置信度，由确定性 ledger 给证据定级。已落地九九住 `lead-scan/judge-prompt.md`（项目层，红→绿验证过：新增「待确认」节把两条旧规则会静默丢掉的线索捞了回来）。本次测的是「该不该从项目层升到 slow-state」。

蒸馏细节见 memory `reference_trycompai_crm_agentic`。

## 方法

按 t67 惯例测**增量**而非「有规则 vs 无规则」：

- **A** = 现有最近邻规则原文（writing.md「事实密集分析标认知来源」+「分析类任务给判断」）
- **B** = A + 新增「证据定级，不自评把握」一节（不输出置信度 / 强证据=第三方指认或可核行为痕迹 / 弱证据只降级不丢弃 / 冲突不折中 / 一个来源算一条 / 不补证据凑数）

两个条件（memory `reference_ab_preference_vs_capability`）：

| 任务 | 条件 | fixture |
|------|------|---------|
| task1 选型：筛「真有生产使用者」的开源库 | **无提示** | 8 个候选，含 2 个强第三方、1 个部分核实、1 个矛盾（README 列 Shopify / Shopify 博客说已迁走）、1 个虚荣指标、3 个纯自述或空 |
| task2 招聘：筛「真在生产跑过 k8s」的 SRE | **有提示**（"上一批有一半只在教程里跑过"） | 7 个候选，含 2 个强第三方、1 个工具名堆砌、1 个证书+教程、1 个时间线矛盾、1 个纯自夸、1 个不相关 |

候选模型 sonnet，每 run 独立 `/tmp` 沙箱 cwd（t65 污染教训）；裁判 opus 盲评，甲/乙 逐任务打乱。prompt 卫生：任务写成真实用户请求，无 t 编号 /「AB」/「评测」字样。

## 结果

四个维度：① 证据定级质量 ② 模糊项处置 ③ 冲突处理 ④ 可核性与可用性。

| 任务 | ① | ② | ③ | ④ | 总分 | 差 |
|------|---|---|---|---|------|-----|
| task1（无提示）A | 8.3 | 7.5 | 8.0 | 8.4 | **32.2** | |
| task1（无提示）B | 9.0 | 9.0 | 8.8 | 8.7 | **35.5** | **+3.3（8.3%）** |

## 行为细节（差在哪）

**冲突处理是唯一的大分差（task2 ③：A 5.5 / B 9.5）。** 材料里 C5 的简历自称主导 k8s 迁移，同期公开 LinkedIn 显示他是前端工程师，且两份材料都是他自己给的。A 把这条写进了淘汰列并定性为诚信问题——证据只支持「有矛盾」，不支持「在撒谎」。B 单开挂起分区，并列了多种冲突解释交回人工。

**「不可核实 ≠ 已证伪」的边界（task1 ①）。** mesh-lite 官网三家客户 logo 有两个点进去 404。A 直接判「那两条是假的」；链接 404 只能推出无法验证。B 降级成不可核实。这是 A 唯一一处把证据级别往上抬的地方，恰好和它自己开头立的判据反向。

**模糊项有没有落脚点（task1 ②：A 7.5 / B 9.0）。** corestream 是这批唯一压不下去的条目。A 的 ✅/⚠️/❌ 一览表把它填成「⚠️ 有条件进」——在表格里已经站到通过侧，下面正文又说「取决于你们能不能接受这个信号」，表格判了散文又收回，转发出去的人只扫表格就当它进了。B 给了独立一节，明写「不做非黑即白的判断」，说清缺的是哪块信息（Shopify 换掉的技术原因博客没写）。

**反直觉的一点：有提示条件的 margin 反而更大**（t67 是反过来的）。提示「上一批有一半是水的」把 baseline 推向更激进的拒绝，A 的过度拒绝正是新条款挡住的失败模式——弱证据不该被「拿不准所以丢掉」，矛盾不该被「拿不准所以定性」。**规则的价值在于挡住用户压力诱发的过度收紧，而不只是挡住过度宽松。**

## 关键结论

1. **KEEP**，触发收窄为「判定/筛选/归类」类产出（判断某条线索是否合格 / 某候选是否符合标准 / 某事实是否成立），不覆盖一般写作和执行任务。
2. 真缺口在**模型对自己不确定性的处置方式**，不在证据识别能力——baseline 认得出「自述 vs 第三方」这条主轴（两份产出都在开头把它立成判据），栽在拿不准的那几条怎么办：往通过侧塞、往淘汰侧塞、或者静默丢掉，就是不肯挂起。
3. 呼应 `reference_ab_preference_vs_capability`：这是**处置偏好类**规则，不是能力类。连败的那串 REJECT 全是能力类（baseline 已自会），偏好类仍是真缺口带——**AB 前先分类**这条再次被验证。
4. 「弱证据只降级不丢弃」这条的落地形态是**一个显式的「待确认」出口**。九九住那次的红→绿证据同源：不给挂起分区，模型宁可静默丢也不会自己造一个。
