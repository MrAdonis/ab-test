- **强证据**：GitHub 主页有一个 300+ star 的 Kubernetes operator 项目，两年持续提交记录。写 operator 要处理 CRD、controller、reconcile loop，这类东西教程环境练不出来，是公开可查、独立于他自述的产出

- 简历自述的"42 节点、跨两可用区、18 个月 on-call"和自我评价"熟悉容器编排"未独立核实，但上面两条强证据已经足够支撑"真的做过生产级 K8s 工作"的判断
- **面试建议追问**：现场讲一下 operator 的 CRD 设计和 reconcile 逻辑；42 节点的故障案例是否就是 meetup 演讲里讲的那次。

### C2 · 李伟 — 通过
- **强证据**：前雇主工程博客上有一篇他署名的技术文章《从虚机到 Kubernetes 的两年》，写明了集群规模、分阶段迁移方案、回滚预案——发布在公司官方渠道，内容有具体到"回滚预案怎么设计"这种程度的技术细节，不是能靠包装临时编出来的
- 简历技能栏只有一行"Kubernetes / Docker / Helm"，信息量很低，但这和上面那篇文章的证据强度不矛盾——反而说明这个人不太会/不在意包装简历
- **面试建议追问**：当时为什么选分阶段迁移而不是一次性切换；每个阶段怎么验证成功，有没有真的触发过回滚。
