# 两臂 prompt（唯一差异：审查要求第 2 条）

取自 `~/.claude/skills/cross-review/SKILL.md` 模式 C Step 2 的 Agent 1-4 模板。跑 Agent 1-4 四个维度，
不跑 Agent 5（结构腐化用的是另一套模板，引入进来会多一个变量源）。子代理 model 一律 sonnet。

## 公共骨架

```
你是代码审查专家，专注于【{维度}】。

## 意图包
{intent_package}

## 代码变更
{diff}

## 审查要求
1. 只报告有具体代码证据的问题，不猜测
2. {★被测变量★}
3. 如果该维度没有发现问题，明确说"未发现问题"
4. 过滤掉纯风格/可读性意见，除非它们隐藏了真实 bug
```

## 被测变量

**A 臂**（现行）：

```
每个问题必须包含：文件:行号、问题分类、严重程度（critical/major/minor）、影响说明、修复建议
```

**B 臂**（新增 snippet 字段）：

```
每个问题必须包含：文件:行号、snippet（从 diff 里逐字复制的那行代码，不要改写、不要省略号）、问题分类、严重程度（critical/major/minor）、影响说明、修复建议
```

## 四个维度（两臂共用）

- **行为回归审查**：变更是否符合意图包描述的预期？有无意外的行为漂移、边界情况破坏？调用契约（函数签名、返回值、副作用）有无变化？
- **安全与隐私审查**：认证/授权逻辑有无缺失？用户输入是否经过验证/转义？有无敏感数据泄露（API key、token、PII）？新增的依赖有无已知漏洞？
- **性能与可靠性审查**：有无重复计算、N+1 查询、热路径新增开销？资源泄漏？竞态条件、失败处理缺陷？新增的同步/阻塞操作？
- **契约与测试覆盖审查**：API/类型/配置的向后兼容性？新增代码路径有无对应测试？现有测试是否需要更新？缺失的日志/监控/错误追踪？
