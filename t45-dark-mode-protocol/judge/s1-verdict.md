# 匿名盲评：s1-design1.html vs s1-design2.html

Brief：团队协作 SaaS「协流」项目仪表盘（顶部导航 + 左侧边栏 5 项目 + 本周概览：4 统计卡 + 8 行任务表 + 纯 CSS 每日完成柱状图），亮暗双模式 + 切换入口，中文界面，单文件 HTML。

---

## Design 1（s1-design1.html）

### 1. 暗色实现质量 — 8.6/10（权重 45%）

- **Token 策略统一**：单一 CSS 变量体系贯穿全局（`--bg/--surface/--text-*/--border-*/--accent*/--success/--danger/--warning` 及各自 tint 变体），light/dark 两套值完全镜像，无遗漏字段。
- **默认尊重系统偏好**：唯一亮点——不靠 JS 读取 `matchMedia` 再赋值，而是用 `@media (prefers-color-scheme: dark)` 配合 `:root:not([data-theme="light"])` 在首屏 CSS 层直接生效，首次访问零 JS 延迟即正确匹配系统深色，且手动切换后仍可覆盖，`color-scheme` 属性也随主题正确设置（影响原生 `<select>`/滚动条渲染）。
- **对比度独立设计**：文本层级三级灰阶（primary/secondary/muted）暗色下明显不同于亮色的直接反色，accent 从 `#4f46e5`（亮色）调整为更亮的 `#818cf8`（暗色）以维持在深背景上的可读性，思路正确。
- **真实缺陷**：`.logo-mark` 硬编码 `color:#fff` 搭配暗色下的 `--accent:#818cf8`（较亮的靛蓝），白字对亮靛蓝背景实测对比度约 **3.03:1**，12px 粗体不满足"大字"豁免线，未达 WCAG AA 正文 4.5:1（小范围徽标，非正文，但确实是"暗色对比度未独立复核"的一个漏网点）。
- **其他**：无 `localStorage` 持久化，刷新后手动选择的主题会被系统偏好重新覆盖（体验上是回退到系统默认，不算错误但不如带持久化完整）。全页无 section 反转，一致性完好；暗色未出现纯黑（`#101014`）/纯白（正文色 `#f4f4f5`）。

### 2. 整体设计品质 — 8.7/10（权重 35%）

- 统计区用分隔线（`border-top/bottom` + 列间竖线）取代卡片+阴影，任务表格、柱状图区块同样只用 `border-top` 分隔，全程无圆角卡片堆叠、无渐变装饰——有效避开"通用 AI dashboard 套路"。
- 排版层级清晰（18px 页标题、16px 区块标题、13px 正文、11-12px 辅助文字),`tabular-nums` 数字对齐,状态标签用色块+圆点双重编码(色弱友好)。
- 中文排版细节到位（字号、间距、日期格式统一）。密度把控适合 B2B 数据面板，不松散也不拥挤。

### 3. 代码质量 — 8.3/10（权重 20%）

- 结构清晰、注释分段明确，CSS 命名语义化，零外部依赖（真正单文件自包含）。
- a11y 覆盖面广：搜索框/切换器/头像按钮均有 `aria-label`（头像按钮甚至带用户名），柱状图用 `role="img"` + 完整文字版 `aria-label` 给出可读替代，导航项 `aria-current="page"`，`:focus-visible` 统一处理。
- 原生 `<select>` 做项目切换器，免费获得键盘可达性和下拉行为（不是关键项但是加分项）。
- 响应式断点（860px）下侧边栏和搜索框直接 `display:none`，移动端完全失去项目列表入口，信息架构有损失。

**加权总分：0.45×8.6 + 0.35×8.7 + 0.20×8.3 = 8.58**

## Design 2（s1-design2.html）

### 1. 暗色实现质量 — 7.4/10（权重 45%）

- **Token 策略统一**：同样单一变量体系贯穿，且比 Design 1 多走一步——定义了 `--accent-contrast` 专门解决"文字压在 accent 色块上"的对比度问题（light 用 `#ffffff`，dark 用 `#08221f` 深色文字压在亮青绿 `#2dd4bf` 上），实测对比度约 **8.96:1**，明显优于 Design 1 同类场景（logo 徽标白字对亮靛蓝仅 3.03:1）的处理。这是本份设计在 token 设计粒度上的真实亮点。
- **致命缺陷——不尊重系统偏好**：`<html data-theme="light">` 在 HTML 源码里硬编码为 light，JS 只读 `localStorage`，从未调用 `matchMedia('(prefers-color-scheme: dark)')`。任何首次访问、系统为深色模式的用户都会先看到亮色界面——这是评分维度里明确列出的检查项，本设计直接不满足。
- 亮色模式主背景为纯 `#ffffff`（虽然 `--bg-elevated`/`--bg-subtle` 有柔和层次，但页面主色是纯白），不完全符合"避免纯黑/纯白"的准则；暗色 `#18181b` 处理得当，非纯黑。
- `--shadow` 变量在亮暗两套 token 里都定义了（且暗色下特意调深了 rgba 透明度），但全篇 CSS 未见任何 `var(--shadow)` 实际引用——定义了却没用上，属于死配置。
- 加分项：JS 用 `localStorage` 持久化用户选择的主题，刷新不丢失（比 Design 1 完整）。

### 2. 整体设计品质 — 8.0/10（权重 35%）

- 表格与柱状图区块套了 `border-radius:10px` 的描边容器，视觉上比 Design 1 更接近常规 SaaS 卡片语言（但未叠加阴影/渐变，克制，不算严重套路化）。
- 引入 Google Fonts「Space Grotesk」给数字单独设计展示字体，为产品增添一点视觉个性/品牌辨识度，是本份的加分细节。
- 密度更紧凑（`line-height:1.4`，行高/内边距略小于 Design 1），对数据密集面板而言更极致。
- 统计区顶部用 `--text` 色而非 `--border` 画粗分隔线，制造更强的视觉起始点，细节讲究。

### 3. 代码质量 — 7.2/10（权重 20%）

- **单文件承诺被破坏**：`<link>` 引入 Google Fonts CDN（`fonts.googleapis.com`），既不是真正自包含的单文件 HTML，也带来离线不可用、外部请求失败时 FOUT/FOIT 的风险——这是与 brief「单文件 HTML」要求直接冲突的实现选择。
- 项目切换器 `.switcher` 视觉上是可点击下拉（带 chevron 图标）但未绑定任何交互逻辑，是纯装饰性假交互；头像用 `<div role="button" tabindex="0">` 而非原生 `<button>`，语义上依赖手动补齐键盘事件处理（本例未补，虽然也未绑定点击逻辑，实际影响有限但语义selection不如原生元素稳妥）。
- 响应式做得更细致：900px 断点下侧边栏转横向可滚动的项目胶囊列表而非直接隐藏，移动端仍保留项目入口——优于 Design 1 的完全隐藏，是响应式维度的真实优势。
- 切换逻辑本身（读取/写入 `localStorage`、图标 innerHTML 替换）功能正确无误。

**加权总分：0.45×7.4 + 0.35×8.0 + 0.20×7.2 = 7.57**

---

## 结论

**胜者：Design 1（s1-design1.html），8.58 vs 7.57**

核心差距：Design 1 在评分维度里明确列出的「默认尊重系统偏好」这条硬指标上完整达标（CSS 媒体查询首屏即生效），Design 2 在 HTML 源码里硬编码 `data-theme="light"`，直接违反这条要求；Design 2 虽然用 `--accent-contrast` token 把"文字压色块"的对比度问题解决得比 Design 1 更彻底（8.96:1 vs 3.03:1），但这个局部优势不足以抵消系统偏好缺失这一更基础的失分。此外 Design 2 引入 Google Fonts CDN 违背「单文件 HTML」的自包含要求，也是其代码质量维度的实质扣分项；Design 2 唯一稳定优于 Design 1 的地方是移动端响应式（保留项目入口）和主题持久化（localStorage）。
