# 夜航 Landing 盲评：Design 1 vs Design 2

## Design 1（s2-design1.html）

**1. 模式策略与实现 — 6.0/10**
纯暗色单模式，无 `prefers-color-scheme` 检测、无 `color-scheme` meta、无浅色回退。品牌逻辑站得住脚（"深夜阅读"App 的落地页用暖金 + 深色传达氛围，且暖色文字 `#f4f1ea` 在深色底 `#12141a` 上对比度足够，不构成可读性硬伤），但执行上完全没有对系统偏好做任何考虑或声明，专业度不如"检测但仍可品牌化默认深色"的做法。单一 `theme-color` 也没有 light/dark 双 meta。

**2. 整体设计品质 — 7.5/10**
文案是本份最大亮点："夜里睡不着，就多读一页" 比对方"深夜，读三十分钟书"更有声音和记忆点。功能区用 feature-row / reverse 交替 + 纸感卡片/书架柱状图两种视觉隐喻，是用心的细节。但 Hero 的"发光光晕 + 旋转手机 mockup"和 Pricing 的"两卡+推荐徽标"都是相当典型的 AI/SaaS 落地页套路（光晕+设备图几乎是同类页面的默认动作），整体布局的独创性弱于对手。

**3. 代码质量 — 8.5/10**
CSS 变量组织清晰，响应式断点按区块精细拆分（900/800/700/640px），reduced-motion 处理完整（含 IntersectionObserver 特性检测降级），focus-visible、44px 触控靶、aria-hidden 装饰元素一应俱全，且 Noto Serif SC 实际通过 Google Fonts 加载（字体承诺兑现）。工程细节完成度高，没有发现明显缺陷。

**加权总分：6.0×0.4 + 7.5×0.4 + 8.5×0.2 = 7.10**

---

## Design 2（s2-design2.html）

**1. 模式策略与实现 — 9.0/10**
真正的双模式实现：`[data-theme]` token 覆盖（浅色暖白纸感 `#f7f4ee` / 深色 `#0d0f14`，均非纯黑纯白），页面加载时 `matchMedia('prefers-color-scheme: dark')` 检测系统偏好，用户可通过顶部按钮手动切换并用 `localStorage` 持久化，两套 accent 色（`#9c5b12` / `#e0a94a`）分别针对各自背景做了对比度适配，toggle 按钮带 `aria-label` 和图标状态切换。这是本次评审里教科书级的消费级产品颜色模式处理。

**2. 整体设计品质 — 8.0/10**
布局原创性明显更强：Hero 用手绘感 SVG 插画（月牙+摊开的书）代替常见的设备贴图；功能区是非对称 bento（7+5+12 跨列，带衬线大号编号）而非三列等宽卡片；testimonials 用左右交替对齐的 pinned quote，避开了卡片网格套路；pricing 是 0.9fr/1.1fr 非对称双栏而不是完全对称卡片。这几处都精准避开了 brief 里点名的"AI 落地页模板感"。文案偏平实、记忆点不如对手强，是唯一的减分项。

**3. 代码质量 — 7.0/10**
Token 架构和 toggle 逻辑扎实，但两处硬伤：① 文件顶部留有生成过程的元注释（"Dial: VARIANCE 7 / MOTION 6 / DENSITY 3"等），这是不该出现在交付代码里的过程痕迹，专业度扣分；② CSS 声明了 `--serif: "Noto Serif SC", ...` 但全文没有任何 `<link>` 引入该 Google Font，意味着大多数非 Mac 设备上标题实际会 fallback 到 Times New Roman 而非设计意图的 Noto Serif SC——这是一个真实的字体加载遗漏，不是风格选择。响应式只设一个断点（860px），粒度不如对手精细。

**加权总分：9.0×0.4 + 8.0×0.4 + 7.0×0.2 = 8.20**

---

## 结论

**胜者：Design 2（8.20 vs 7.10）**

核心差距：Design 2 在颜色模式维度做了完整的专业级处理（系统检测+用户覆盖+双模 token parity），且布局原创性更强、更彻底避开 AI 落地页套路；Design 1 靠更强的中文文案和更完整的工程细节（尤其是真正加载了声明的字体）部分追回分数，但暗色单模式缺乏对系统偏好的任何考虑，且 Hero/Pricing 结构落入常见 SaaS 套路，综合仍落后一分左右。
