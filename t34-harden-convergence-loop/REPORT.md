# t34 — harden 式同模型收敛循环 vs baseline 方案压测

**日期**：2026-06-23
**来源**：BohuTANG (@BohuTANG) 推文 + `evotai/evot` 的 `harden.md` skill。原始主张「同模型两轮收敛 `/harden` 比跨模型 review 快且效果好」。速度优势无法做质量 AB，本测只验证 harden **结构本身**在「实现前方案硬化」任务上的质量增量。
**被测变量**：baseline 裸压测 vs 加一整套 harden.md 式收敛循环（列具名漏洞 → 修复或显式接受风险带理由 → 重查修复引入的新漏洞 → 防膨胀护栏 → 收敛/上报判据 → 自包含 final plan 输出）。
**方法**：Sonnet ×12 生成（6 场景 × A/B，各独立子代理 context）；Opus ×6 盲评（甲/乙 匿名，评委先独立推导 ground-truth 再打分，显式 anti-length-bias + 编造漏洞倒扣）。盲序映射见文末。

## 结论：REJECT（不整块引入配置）

总分 **B 44.0 vs A 41.1**（+2.9，约 7%），表面达到过往 KEEP 量级。但拆开三轴后，这个分差的来源决定了不能 KEEP。

## 为什么 REJECT —— 三轴分解

**+2.9 的总分差里，+3.1 来自被 prompt 直接 prime 的两个防膨胀场景（S2 +1.6、S6 +1.5）。** B 的 prompt 逐字列了「Fallback 泛滥 / 抽象蔓延 / 范围漂移」四条护栏，而 S2/S6 恰好考克制——B 在这两场赢「显式接受风险段 + out-of-scope 声明」是必然的 teaching-to-test。这部分增益不能算给 harden 结构本身。

**剔除 S2/S6 后，找真漏洞轴（S1/S4/S5）B 确实不输**（S1 平、S4 平、S5 +0.7），通过了预设的「不被判 teaching-to-test」硬门。但通过这道门只是「没被取消资格」，不等于「值得引入」。剥掉泄题增益后，B 的真实非冗余优势收窄到**几乎只剩 S5 一场**——靠收敛循环的「重查」第二遍抓到了 A 漏掉的回滚方案。S1/S4 两场评委都明判平手。一场的边际收益。

**S3 暴露了 harden 结构一个真实的、非泄题的反向伤害。** 实时协作每 2 秒整文档覆盖 = last-write-wins 必丢数据，正确处置是上报「同步模型根本不对、该换 OT/CRDT」而非打补丁。结果 B（harden arm）正是被评委点名的「假完成」案例：它忠实执行「列漏洞→修→重查→收敛」，把错误地基上的方案糊成一份"可直接执行的整套规格"（10 个漏洞、2 轮、SQL+API+状态机全套），工程仪式感最足，离正确越远。A 反而更克制、且说出了「这个 MVP 验证的是假需求」的判断。**harden 的「收敛而非升级」默认偏置，在该升级的场景会主动制造假完成。**

## 判断

这是一次「硬门通过、但整体仍 REJECT」的案例，三条理由：

1. **真实非冗余增益太薄**：剥掉泄题的 S2/S6 后只剩 S5 一场，S1/S4 平手。不够支撑新增一块配置面。
2. **重复覆盖**：现有配置已三处覆盖 harden 想加的东西——方案压测有 `/cross-review redteam` + `/grill-me`；防膨胀有 `coding.md` 的过度设计判据 / 反范围蔓延 / Rationalization Watch；该升级别打补丁有 `coding.md` 的「Rewind 优先于继续修补」+ `brainstormer` 升级路径。整块引入 = 复制三个已有机制。
3. **引入反向伤害**：S3 证明 harden 的收敛偏置会在「设计本身错」场景压制升级、制造假完成，恰好是现有 Rewind/escalation 机制要防的事。

符合 `wiki-lifecycle.md` §① 少而准（别堆料）、t31「baseline 不蠢就别加」、t14「覆盖面压倒性别双注册抢触发」的既有谱系。按 `feedback_ab_test_on_integration`「无提升则回滚」——这里是「有名义提升但来源不正 + 带反向伤害」，同样不并入。

## 唯一真实小金块（记录，不采纳）

harden 循环步骤 3「重查——这些修复有没有引入新漏洞」是 S5 唯一真实赢点的来源，而 `coding.md` 假设驱动调试的 CONCLUDE 步只写到「根因确认 → 修复 + 回归测试」，**没有显式的「修复自身是否引入新漏洞」自查回环**（部分活在「修复验证失败→回 HYPOTHESIZE」里，但那是针对修复失败，不是修复成功后的二阶自查）。这一条单独看有边际价值，但单场景证据太薄，不足以单独入配；要采纳需为它单跑一个 AB，本测不据此动配置。
