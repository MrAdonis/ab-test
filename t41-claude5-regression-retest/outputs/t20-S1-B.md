JS 是单线程的,靠 event loop 来调度同步代码、宏任务(macrotask)、微任务(microtask)。整体规则是:先把当前这一轮的同步代码跑完,然后清空微任务队列(清空过程中新产生的微任务也会被继续处理,直到队列真正空了),再从宏任务队列里取一个执行,执行完之后又去清空微任务队列,如此循环。也就是"一个宏任务 + 该轮产生的所有微任务"算一轮。

同步任务就是主线程上按顺序直接执行的代码,包括函数调用、`console.log` 这些,没有任何"排队"概念,写在哪就按顺序跑到哪。

宏任务包括整体脚本代码本身(可以理解为第一个宏任务)、`setTimeout`/`setInterval`、`setImmediate`(Node)、I/O、UI 渲染、`postMessage`、以及 Node 里的 `close` 回调之类。宏任务队列里的任务是一个个取出来执行的,每次只执行一个。

微任务包括 `Promise.then/catch/finally`、`queueMicrotask`、`MutationObserver`、以及 Node 里的 `process.nextTick`(注意 Node 里 `nextTick` 队列优先级比普通微任务队列更高,会先清空 nextTick 再清空 Promise 微任务)。微任务队列是每次都会被清空干净的,不是只执行一个。

一个常见误区是把微任务和宏任务当成同级别的"下一轮",实际上微任务永远插在两个宏任务之间,而且优先级更高——哪怕微任务里不断产生新微任务,也会一直执行下去(理论上可能饿死后续的宏任务和渲染)。

举个例子帮助建立直觉:

```js
console.log('1');

setTimeout(() => console.log('2'), 0);

Promise.resolve().then(() => console.log('3'));

console.log('4');
```

执行顺序是 `1 4 3 2`:同步代码 `1`、`4` 先跑完,然后清空微任务打印 `3`,最后才轮到宏任务里的 `setTimeout` 打印 `2`。

浏览器环境里还有一点要注意:每次宏任务执行完、微任务清空完之后,浏览器可能会做一次渲染(rendering),所以微任务多、耗时长会阻塞页面重绘;Node 环境里没有渲染这一步,但多了 `timers → pending callbacks → poll → check → close callbacks` 这几个阶段,`setTimeout` 和 `setImmediate` 谁先谁后要看具体调用时机(在 I/O 回调里 `setImmediate` 总是先于 `setTimeout` 执行)。
