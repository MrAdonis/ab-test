JS 是单线程的，靠 event loop 协调「调用栈」和「任务队列」。核心顺序：

**1. 同步任务**
所有同步代码直接进调用栈，按顺序执行，跑完为止。这一步不涉及队列。

**2. 微任务（microtask）**
来源：`Promise.then/catch/finally`、`queueMicrotask`、`MutationObserver`、`async/await` 里 await 之后的部分。

规则：**每当调用栈清空一次（一个同步任务块跑完），就把微任务队列清空**——不是只执行一个，而是执行到队列为空为止，包括微任务执行过程中新产生的微任务也会在本轮清完。

**3. 宏任务（macrotask / task）**
来源：`setTimeout/setInterval`、`setImmediate`（Node）、I/O、UI 渲染、`MessageChannel`、script 整体执行本身也算一个宏任务。

规则：每次从宏任务队列取**一个**任务执行，执行完（同步部分跑完）后，立刻清空一遍微任务队列，然后才会考虑渲染或取下一个宏任务。

**整体循环模型：**
```
执行一个宏任务(如整个script)
  → 清空微任务队列(直到空)
  → (浏览器可能触发渲染)
  → 取下一个宏任务
  → 清空微任务队列
  → ...循环
```

**例子：**
```js
console.log('1');                 // 同步

setTimeout(() => console.log('2'), 0);  // 宏任务

Promise.resolve().then(() => console.log('3')); // 微任务

console.log('4');                 // 同步
```
输出：`1 4 3 2`

原因：同步代码先跑完(1、4) → 栈空，清微任务(3) → 再取宏任务(2)。

**常见坑：**
- `async function` 里，`await` 之前的代码是同步执行的；`await` 之后的代码相当于被包进 `.then`，是微任务。
- 微任务队列没清空前，绝不会执行下一个宏任务或渲染——所以**微任务里死循环递归添加微任务会饿死渲染和宏任务**（页面卡死的常见原因）。
- Node.js 里还细分了 `process.nextTick`（比普通微任务优先级更高，先于 Promise 微任务清空）和 `setImmediate` vs `setTimeout(fn,0)` 在不同阶段的先后关系（比较复杂，浏览器环境不用管这个）。

一句话总结：**同步先跑完，每轮同步/每个宏任务后必须先把微任务队列榨干，才轮到下一个宏任务或渲染。**
