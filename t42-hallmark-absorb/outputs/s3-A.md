# 竖版长图海报审查清单（品味维度）

## 使用说明

本清单供审查 agent 在 **design-lint 脚本跑完之后** 使用，覆盖脚本无法机器判定的品味维度。两者分工：

- **design-lint（已跑，40 条确定性规则）**：对比度阈值、最小字号绝对值、overflow、reduced-motion 等——本清单不重复。
- **本清单**：主观品味类判断，凡能拆成阈值的已拆（带依据），真拆不出来的保留文字描述，不装假阈值。

审查对象：已 build 好的海报 HTML/截图（1080×N px 竖版长图）。

对每条给出 `PASS` / `FAIL` / `NEEDS_REVIEW`（无法仅凭本条判定，需人工复核）/ `NOT_APPLICABLE`，并附一句证据说明（看到了什么、量了什么）。格式见文末「输出格式要求」。

---

## 1. 信息密度与视觉焦点（对应"别排太满/重点信息一眼看到"）

- **1.1【可测】留白占比 ≥30%**：目视估算画面中非文字、非图形的空白区域占比。
  依据：Calimari Rule——信息密度越低，感知档次/高级感越高。
- **1.2【可测】主视觉焦点唯一**：画面中尺寸×对比度综合最高的单一元素，必须对应核心信息（活动主标题/主视觉），不能是装饰性图形或次要信息抢占最大视觉权重。
  依据：视觉层级理论的单一焦点原则（Gestalt figure-ground）。
- **1.3【无法量化，保留文字】** 留白节奏是否舒适、整体"高级感"是否成立，最终目视判断——1.1 数字达标不代表 1.3 一定通过，两者独立打分。

## 2. 主标题冲击力（"要有冲击力但别用力过猛"）

- **2.1【可测，范围校验非硬阈值】** 主标题字号高度占画布宽度比例建议在 8%-18%（1080px 宽画布约 86-194px）。
  依据：常见竖版社交海报/Banner 主标题字号惯例，超出范围标 `NEEDS_REVIEW` 而非直接 `FAIL`（惯例不是硬约束）。
- **2.2【可测】主标题同时叠加的文字特效（描边/阴影/渐变/发光）种类计数 ≤2**：超过 2 种视为"用力过猛"信号，同时与第 4 节（AI 味）联动判断。
  依据：与本规范模式 10a 一致的堆叠计数法，避免多种特效叠加造成的视觉噪音。
- **2.3【无法量化，保留文字】** 若 2.1/2.2 均达标但目视仍觉浮夸（满屏拉伸变形字、极端透视文字等），人工标注具体原因，不可仅凭前两条数字判 PASS。

## 3. 配色克制，以品牌色为主

- **3.1【可测】60-30-10 色彩比例**：主色（品牌色）占比约 60%，次色约 30%，点缀色约 10%，允许 ±10% 浮动。
  依据：经典设计配色惯例，广泛用于平面/UI 配色控制。
- **3.2【可测】独立可辨识色相（hue）数量 ≤4**（不含黑白灰中性色）。
  依据：Cleveland & McGill 1984（颜色可辨识上限 5-7），"克制"要求取更保守值。
- **3.3【可测】品牌色主导地位**：品牌色（需交付时提供 HEX 值列表）必须在主标题/主视觉焦点/CTA 中至少一处占据最大面积或最高对比度。
  依据：与 3.1 的 60% 主色占比呼应，防止"品牌色只出现在角落"这类挂羊头假达标。

## 4. 避免一眼 AI 味的元素（枚举式反模式清单，命中 ≥2 条判 `FAIL` 需返工）

逐条判 Yes/No：

- 4.1 背景是否用了无意义的抽象流体渐变/光斑 bokeh，且与内容无实质关联
- 4.2 是否玻璃拟态（glassmorphism）与霓虹发光（neon glow）同时叠加使用
- 4.3 图片中人物/手部/文字是否有结构畸变（多指、扭曲肢体、乱码文字）
- 4.4 装饰性图形元素是否与海报主题无逻辑关联（纯粹"看起来很酷"但零信息量）
- 4.5 视觉元素是否整体过度平滑/塑料感，缺乏材质、纹理、颗粒等真实感细节
- 4.6 文字特效是否堆叠过多（复用 2.2 判定结果）

依据：以上是设计社区对"AI 生成图像视觉特征"的普遍归纳，非单一学术出处，标注为经验清单（枚举本身即降低了主观判断的自由度，符合"能枚举不靠 judgment"原则）。

## 5. 图片和插画处理风格统一

- **5.1【可测】图片/插画类型计数 =1**：全图出现的视觉素材类型（摄影 / 插画 / 3D 渲染 / 图标）不应混用，除非交付说明中明确标注"有意做混合风格"。
- **5.2【可测】多图同框时色调方向一致**：饱和度、色温方向需统一（不可一张高饱和暖色、一张去色冷色并存）。
- **5.3【可测】处理参数统一**：圆角、描边、投影等处理手法在全部图片/插画间保持一致（同一套视觉语言）。

## 6. 文字层级分明，正文别太小（不重复 design-lint 已测的绝对最小字号）

- **6.1【可测】层级数量 3-4 级**（主标题 / 副标题或时间地点 / 正文 / 辅助说明）。
  依据：Type scale 模块化字号阶惯例。
- **6.2【可测】相邻层级字号比例 ≥1.25 倍**，低于此比例视觉上难以区分层级。
  依据：模块化字号阶（Modular Scale），Major Third = 1.25 是常见下限。
- **6.3【可测】正文字号相对定位**：正文（非强调文字）应为全图第二小字号，仅大于辅助/免责说明文字，不应与主标题字号接近导致层级混淆。

## 7. 底部落款（logo + 二维码）别喧宾夺主

- **7.1【可测，经验阈值】落款区域总高度占画布总高度 ≤10%**（logo + 二维码 + 相关文字整体）。
  依据：常见社交长图/海报品牌区惯例，非学术出处，超出标 `NEEDS_REVIEW` 而非直接 `FAIL`。
- **7.2【相对比较，非绝对阈值】** 落款区域的视觉权重（尺寸 × 饱和度 × 对比度综合）应明显低于主标题区域，不应是全图最大色块或最高对比度色块——用"和主标题比谁更抢眼"代替绝对数字，可直接目视比较，不需要额外学术依据。
- **7.3【边界声明】** 二维码尺寸下限（可扫描性）不属于本条范围，由 design-lint 或平台规范另行约束——本条只管"是否太大喧宾夺主"，不可因为追求"别喧宾夺主"而把过小、可能扫不出的二维码误判为合规。

## 8. 不同活动海报要能分清是哪场活动

- **8.1【前提声明】** 这本质是"跨海报对比"任务，单张海报审查无法完全判断"是否和其他海报撞脸"，除非同时提供同系列历史海报作参照。以下是拆给单张审查可执行的代理检查（proxy check），不是完整替代：
- **8.2【可测】活动名称/主题必须以主标题或副标题形式独立存在**（不能只靠图案暗示），字号不低于 6.1 定义的第二层级。
- **8.3【可测】关键信息完整**：时间/地点/形式必须以独立可读文字块存在，不能缺失或被图形遮挡。
- **8.4【条件触发，需参照图】** 若交付时提供了"同系列其他活动海报"作参照，需核对：主色调/主视觉图形/插画主体是否有明显差异化元素（色相偏移、专属图标、专属插画主体），不能是仅替换文字的同一模板复用。无参照图时本条标 `NOT_APPLICABLE`，不可臆测判定。
- **8.5【无法量化，保留文字】** 差异化"够不够"最终是主观判断，agent 需在输出中具体写出"哪些元素变了/哪些没变"，供人工复核，不能只给一个 PASS/FAIL 结论了事。

---

## 输出格式要求

审查 agent 逐条输出，不得跳条，不得合并输出成一段笼统评语：

```json
{
  "item": "2.2",
  "verdict": "PASS | FAIL | NEEDS_REVIEW | NOT_APPLICABLE",
  "evidence": "看到/量到的具体事实，如：主标题叠加了描边+阴影+渐变共3种特效"
}
```

标 `NEEDS_REVIEW` 的条目必须说明"为什么本条不能由 agent 独立判定"（如 2.1 超出惯例范围、7.1 超出经验阈值、8.5 主观判断），不能滥用 `NEEDS_REVIEW` 逃避判断——凡是本清单标注【可测】的条目，agent 应优先给出 PASS/FAIL，只有真正触及模糊边界时才升级 NEEDS_REVIEW。

全部条目跑完后，统计 `FAIL` 数量：0 个 `FAIL` 且 `NEEDS_REVIEW` ≤2 个 → 建议通过；否则列出具体条目交回设计者修改，不给整体"良好/一般"这类模糊评级。
