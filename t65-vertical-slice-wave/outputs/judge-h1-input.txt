===== 推文甲 =====
219字，符合260字以内的要求。

MCP 和 Skills 不是一层的东西。MCP 是协议层：鉴权、连接、常驻进程，解决"怎么连上外部系统和数据"。Skills 是知识层：一堆 prompt+脚本，纯文本能进 git diff，解决"这类任务该按什么流程干"。见过不少人为了跑个脚本硬套一层 MCP server，鉴权配置比逻辑本身还长——那其实就是 Skill 的活。我的判断：要接活的外部系统上 MCP，要模型每次行为一致先写 Skill，别把能静态化的流程做成服务。

MCP 和 Skills 别搞混：MCP 解决「连接」问题——给 Claude 接上外部系统（数据库、API、SaaS），本质是协议加服务器，重一点但换客户端能复用。Skills 解决「怎么做」问题——一份 markdown 说明书加脚本，按需加载，不占常驻上下文，写起来是分钟级的事。我的判断：能用 Skill 解决的别上 MCP，很多人为调一个 API 就搭整套 MCP server，其实 Skill 里塞几行 curl 就够。真正该上 MCP 的场景，是要维持鉴权和状态的实时外部连接，其余大多是过度工程。
