很多人拿 MCP 和 Skills 当竞品比，比错了。

MCP 解决"模型够不着"——数据库、OAuth、别人家的服务，得有个进程替你握手。Skills 解决"模型不知道该怎么干"——一份 markdown，把流程和坑写清楚。

分界线：要跨进程拿数据和权限的上 MCP；本机 Bash 一行能跑的写进 Skill，别包一层协议。

代价也不对称。MCP 的 tool schema 常驻 context，装十个 server 光 schema 就吃掉上万 token，会话中途增删还炸缓存。Skill 不触发零成本，触发了才读那几百行。

所以默认顺序是先问能不能用文件和脚本解决，不能再找 MCP。倒过来的人，context 就是这么烧没的。
