# t41 场景与评分定义

被测问题：在 design-system 基线上叠加 ui-ux-pro-max-skill（nextlevelbuilder，★99k）是否产生可测的前端产出提升。

- **Variant A**：design-system SKILL.md 原版（现行基线）
- **Variant B**：A + ui-ux-pro-max（按其自身使用方式完整可用，含数据检索工具如有）
- 判定规则：B 均分未超过 A → 不装（沿用 t14「无提升则回滚」）

## 生成协议

- 6 个 Sonnet 子代理（3 场景 × A/B），各自只读对应 variant 的上下文，互相隔离
- 产出：单文件 HTML（inline CSS），无外部依赖（字体可用系统栈或 CDN 声明但不强求加载成功）
- 每代理只做一个场景，不看其他场景产出

## 场景（沿用 t14 三原型、全新 brief，避免记忆解）

### S1 中文 SaaS landing —「潮汐」团队协作看板

为一款名为「潮汐」的中文团队协作看板工具做营销落地页。目标用户：10-50 人的国内创业团队。
必含区块：hero（含一句主张 + CTA）、3 个功能点、定价（免费/团队/企业三档）、页脚。
考察：中文排版质感、反 AI 审美（不落 hacker green / emoji icon / radial glow / 紫渐变）、主张文案与视觉的一致性。

### S2 英文 creative portfolio — 独立陶艺工作室

为一家名为 "Kiln & Tide" 的独立陶艺工作室做作品集站。手工陶器，海岸风格，接受定制委托。
必含区块：作品画廊（≥6 件，可用占位图但排版必须是设计的一部分）、about、commission 询价入口。
考察：艺术方向与记忆点（这个页面唯一会被记住的是什么）、图文关系、非模板感。

### S3 反向场景 dashboard — 物流车队监控

为物流公司做车队实时监控后台：在途车辆列表（≥8 行，含状态/位置/ETA/异常）、关键指标卡（准点率/在途数/异常数/今日完成）、告警流。
考察：信息密度与克制（反向场景——装饰性设计规则在此应让位于可用性）、状态色语义、扫读效率。
此场景用于检测 B 是否把装饰性规则错误泛化到工具型界面。

## 评分（沿用 t14 权重）

- 场景适配 30%
- 反 AI 审美 30%
- 设计完成度与记忆点 25%
- 可用性硬指标 15%（对比度、层级、响应式基本盘）

## 评审协议

- 每场景 3 个 Sonnet 盲评 judge，双盲（只见「设计稿 1 / 设计稿 2」，A/B 顺序每场景随机并记录 key）
- judge 各自独立打分出四维 + 总分 + 一句关键证据
- 汇总取均分；单场景差距 <0.3 视为该场景平手
