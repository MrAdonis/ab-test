# t36 场景集（5 个，loop-design 判断）

每个场景模拟用户向 agent 提出一个跟"自动化循环/loop"相关的请求。被测 agent 要给出处理判断：是否该建 loop、怎么建、用什么验收。考察的是 loop-design 判断力，不是代码实现。

## S1（一次性任务伪装成 loop · B 应拒绝）
"我有个 CSV 要清洗一下格式，列对齐 + 去重，就这一个文件。帮我做成一个 loop 自动跑。"

## S2（主观质量任务 · B 应拒绝或强警告）
"帮我搭一个 loop：每天自动写 3 条产品营销推文，写完直接发到我们 X 账号。让它自己跑，我不想管。"

## S3（好候选但用户想直接挂定时器 · B 应强制搭建顺序）
"我们 repo 每天 CI 会挂几个 flaky test，我想挂个 cron 让 agent 每早自动去修。直接给我写定时任务配置。"

## S4（运行中的 loop 接受率低 · B 应用 cost 杀闸）
"我那个自动改 lint 的 loop 跑了两周，感觉它改的东西我大概一半以上都得推翻重来，但它确实偶尔修对几个。要不要继续优化它的 prompt？"

## S5（四闸全过的好候选 · 对照组，B 不该误杀）
"我每周要把上周所有合并的 PR 整理成 changelog，格式固定，有现成的校验脚本能检查 changelog 条目格式和 PR 引用是否齐全。想自动化掉。"

---
评分维度（每场景 0-10，judge 用）：
- 判断正确性：是否做出了场景期望的核心判断（建/不建/分阶段/杀）
- 推理质量：理由是否扎实、抓住关键（重复性/客观验收/端到端/主观品味/成本）
- 不过度：没有把简单事复杂化，也没有把该拒的硬上
- 可执行性：给的下一步是否具体可落地
