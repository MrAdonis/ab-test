# t74 — grill-me 终止契约与收口结构

2026-08-21。来源：一篇公开长文里的苏格拉底提问 prompt 含三条本地 `grill-me` 没有的约束，作者本人顺带点出「这类 skill 会一直拷打我导致我很烦」。核对 `~/.claude/skills/grill-me/SKILL.md`（全文 10 行）确认：只有「一次问一个」「每问给推荐答案」「能查代码就查代码」，**没有任何终止条件**，字面写的是 relentlessly。

## 假设

给 grill-me 加三条——(a) 每问前说明上一答更新了什么理解、(b) 只问可能改变结论的问题且信息够就停、(c) 结束时按六段收口（最初的问题 / 真正要解决的问题 / 已确认事实 / 未验证假设 / 最可能改变结论的变量 / 一个可行动的新问题）——能提升追问效率与终止时机，且不损害领域质量。

## 设计

交互式 skill 单轮跑法测不出「会不会停」，所以自建多轮 driver（`driver.py`）：被测臂（顾问）与固定人设的用户模拟器交替对话，最多 12 个顾问轮次。

- A 臂 = 现行 SKILL.md 原文；B 臂 = 原文 + 三条。两臂均 `--model sonnet`。
- 用户模拟器持有一张封闭事实卡（task1 九条 / task2 八条），**卡外一律回答「没想过 / 不知道」，禁止编造**。这样「信息已挖尽」有客观时刻，顾问是否还在空转可被观测。
- 模拟器每轮输出 `TAG: ASKED|SUMMARIZED` 判定对方是在要信息还是在收尾，driver 据此判自主停止。TAG 是评测基础设施，不进被测臂上下文。
- 全程 `--disallowed-tools`，纯对话。冒烟测试发现不限制时模型会跑去翻本机真实目录，耗轮次且污染 transcript。
- 任务 prompt 无评测线索。task1 技术方案（小程序会员订阅），task2 主观决策（要不要接长期外包）。
- 盲评用 opus，甲乙位置在两任务间交叉（`judge/mapping.txt`），rubric 见 `judge/rubric.md`。

## 判定：分裂，不入配

**task1（技术方案）B 压倒性胜出**，且赢在靶点上。B 在用户答不出可验证技术事实时当场判定「剩下的不是问你，是你去翻代码」并收尾，六段收口把未验证假设收敛到单一变量、下一步具体到 `notify_url` 回调函数级。A 则把同一个支付方式问题换皮问了两遍，自己写着「跳过这条」又接着问，最后清单里还冒出一个与全文 199 打架的 195。

**task2（主观决策）B 小负 5 分**，且终止契约完全没触发——B 第 12 轮仍在开新问题分支（已核实最后一轮发言，不是被 max_turns 截断，截断不对称的怀疑被数据推翻）。裁判评述指出两臂都没收口，B 还把同一个报价问题挥棒三次。5/60 ≈ 8%，低于 `HELDOUT.md` 记录的 ±12% 单 run 噪声基线，本身无分辨力；有分辨力的是**「信息够就停」这条在没有客观终点的主观决策场景里根本没生效**。

按「无提升则回滚」的严格标准，优势只在一类任务上复现，不足以直接进 slow-state。

## 方法论缺陷（下轮修）

1. **样本量不足**：2 任务 × 1 run，且两类任务各只有一个样本，无法区分「B 只对技术类有效」和「task2 设计有问题」。persona2 八条事实中大量是主观倾向而非可核事实，用户「没想过」的密度天然更高，可能任何顾问都收不了口。
2. **max_turns=12 是硬截断**，对有收口契约的臂理论上不对称（本次经核实未发生，但样本一多就会撞上）。下轮应改成到上限时给双臂同一句「请收尾」，把「收口质量」与「终止时机」拆成两个独立可测量。
