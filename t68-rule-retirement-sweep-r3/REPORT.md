## 逐靶详情

### T1 · 轨迹可审

任务：设计一个 40 子代理并行安全审计 workflow 的产出结构（每个子代理产出什么 + 汇总长什么样），要求能直接落到脚本里。

clean 臂给出的是一份合格的索引：`fixDiffSummary` 是散文描述、`filesReviewed` 文件清单、`false_positive_noted` 误报留痕、完整可跑的 `aggregate()`。但它没有证据片段、没有独立 verify 阶段、没有 `tests_run`、没有 `residual_risk`——裁判的判词是"你拿到报告后仍然要自己把 40 个模块的 `git diff` 从头看一遍，那这份报告只是个索引，没有降低你的复核成本"。

规则臂加出来的正好是规则那三句（改了什么／依据哪条判定通过／证据多硬）的字面映射：`evidence` 存原始代码片段、`fix_diff` 存 unified diff 而非自然语言、独立的 `VERIFY_SCHEMA` 作 pipeline 第二 stage（`diff_safe` / `issues` / `tests_run`）由另一个代理复核、`residual_risk` 强制修没修都填，外加"修复口径写进 prompt"（critical/high + confidence=high 才自动改）。裁判点评："方案一大胜，这是决定名次的一项。"

B 唯一输的维度是 (a) 落地性 6 vs 8，根因是它 pipeline 片段里一个真 bug（`: null` 把未修复模块的 audit 数据整条丢掉），与规则内容无关。

**结论**：margin 没有继续塌缩，反而在规则自己瞄准的那根轴上打回来了。更重要的是 t40 自报的检索盲区——"收窄后的精简版 vs 原全文版未经实测对比"——在这一轮被闭合：现在正文里的精简版本身是直接测过的。

### T2 · 检索盲区

任务：给一个调研子代理（AI coding agent harness 的权限边界与沙箱设计）写委托 prompt，包括要它返回什么、什么格式。

靶向维度 B 赢得干脆：8 vs 5。裁判："「检索盲区」要求代理自报用了哪些检索角度、刻意没覆盖什么——这是你唯一能反向估算漏了多少的抓手。方案一给 5 分而不是更低，是因为它要求逐条附引用 + 允许说'信息不足'，你至少能抽查；但引用只证明有人这么写过，不证明代理读过、也不告诉你它没搜过什么。"

B 的总分失分全部落在同一条规则里绑着的 `≤1500 token`：
- 覆盖面 8 vs 6——为守这个数，B 从调研清单里砍掉了 Claude Code（"目前公开权限模型最细的一个，恰好是你这个课题的最佳样本"）和 Open Interpreter（"几乎不隔离"档的典型对照组），问题维度从 6 条压到 4 条
- 格式自相矛盾——要求"对每个项目分别回答 4 个问题"，但输出格式里只有表格 + token 上限，没有 per-project 小节
- 单位本身不可执行——"子代理估自己的 token 数一向不准，写「≤N 字」或「表格 ≤N 行」才是可执行的约束"

裁判定性："方案二是**取舍方向对、刻度错了**"，处置建议"选方案一，但必须把方案二的三段移植进去"（WebSearch 取证 / 遗留问题 / 检索盲区），篇幅约束改成可执行单位。

**结论**：规则本体 KEEP，同句的篇幅约束改刻度。已落到 `~/.claude/rules/coding.md:100`——`≤1500 token` → `≤1200 字`，并显式声明该上限管回传摘要而非调研深度。这条措辞修正未单独 AB（它修的是本轮实测出的副作用，不是新增行为），观察到反效果即回滚。

## 元结论

1. **两条都不该退役。** 这一轮扫的是台账里 margin 最小的两条，结果都在自己瞄准的轴上大比分保住——说明 §④ 的"margin 最小优先"排序确实把最可疑的先捞了上来，且这批 Sonnet 5 baseline 还没自发学会。

2. **发现一类新的规则缺陷：捆绑条款的副作用。** 一条 bullet 里塞两个独立要求（篇幅上限 + 检索盲区），盲评会把两者的效果混在一个总分里。t40 用 Fable baseline 测这条时是净正（+0.7），这轮拆开看才发现正的那半和负的那半同时存在。**AB 的粒度必须对齐规则的粒度**——多要求的 bullet 应该拆开测，否则一个负向条款可以藏在一个正向条款背后好几轮。

3. **t40 的自报盲区值回票价。** 轨迹可审当年收窄时留了一句"精简版未经实测对比"，这轮直接指向了该测什么。检索盲区这条规则在为自己的元层面作证。

## 局限

- 每条规则各 1 个任务、1 名裁判、单轮——不是统计量，是定性证据。结论只在"靶向维度出现决定性分差"这个强信号上成立，总分小差距（≤1）不作数
- t1 的 B 臂被一个与规则无关的代码 bug 拖了 (a) 维度 2 分，若无该 bug 差距会更大——这是低估不是高估，不影响 KEEP 结论
- t2 的规则文本在测试时是捆绑的，所以"检索盲区单独一条能拿多少分"没有直接测量，只有裁判的归因分析
- 篇幅约束的修正版（≤1200 字 + 作用域声明）本身未测
