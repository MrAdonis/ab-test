你是内容评委。同一个请求下两位写手交回的推文（甲/乙）。请求：把「MCP 和 Skills 的区别」写成一条 260 字以内的中文推文，读者是天天用 Claude Code 的开发者，别写成科普腔，要有自己的判断。

评审维度（各 0-10）：hook 强度 / 信息密度 / AI 腔（反向，越有 AI 腔越低）/ 判断是否鲜明。最后回答：甲乙哪条更值得直接发出去？差距是明显还是接近？

## 甲

MCP和Skills根本不是同一层的东西,别老拿"哪个更强"比。

MCP是连接器,给模型接入外部世界的手(读数据库、调API、控制浏览器),本质是运行时的能力扩展,活的、有状态、能来回交互。Skills是知识包,一堆写好的判断力和流程放那等你触发,本质是prompt工程的组织方式,静态的、按需加载进context。

真正该问的是"这次要新增行动能力,还是要注入已有判断力"——前者装MCP,后者写skill。见过不少人把该写成skill的经验硬塞进MCP tool description里,又臃肿又没法复用;也见过把该用MCP做的实时查询硬写成skill里的"假设xxx",两个都是错的方向。

## 乙

MCP 给的是接口——一堆工具挂在那，能不能用对全靠你 prompt 里怎么调。Skills 给的是知识——一份写好的操作手册，Claude 自己判断什么时候翻出来读。

所以真正的分工不是"谁功能强"，是谁该管"何时该做"。你要连一个外部系统（数据库、浏览器、第三方 API），上 MCP；你要固化一套判断逻辑（什么时候用什么风格、踩过的坑、内部规范），写 Skill。

日常最容易踩的坑是反着用：拿 MCP 硬塞进一堆本该是文档的东西（污染 context、每次都要显式调用），或者指望 Skill 去连它管不了的实时数据源。判断标准就一句话:需要连接,用 MCP;需要判断,用 Skill。
