## 打分

| 维度 | 甲 | 乙 |
|---|---|---|
| hook 强度 | 8 | 6 |
| 信息密度 | 8 | 7 |
| 无 AI 腔 | 7 | 5 |
| 判断鲜明 | 9 | 7 |

## 逐条说

**hook。** 甲开口就是"别老拿哪个更强比"，先否掉一个读者可能正抱着的错误问法，天然带对抗性，开发者刷到会停。乙第一句是"MCP 给的是接口"——信息来得快，但本质是定义开场，没有让人停下来的张力，读起来像文档摘要的第一行。

**信息密度。** 两条都不水。乙有一处比甲准：说 Skills 是"Claude 自己判断什么时候翻出来读"，抓到了模型自主触发这层机制；甲写成"放那等你触发"，暗示是用户触发，措辞不严谨。但乙也栽在同一片地里——它说 MCP"能不能用对全靠你 prompt 里怎么调"、"每次都要显式调用"，这是错的，MCP 工具同样由模型自主决定调不调。给天天用 Claude Code 的人看，这条会被当场挑出来。甲那处是措辞松，乙这处是事实错，后者更贵。

甲的负例给得更狠也更具体："把该写成 skill 的经验硬塞进 MCP tool description 里，又臃肿又没法复用"——有画面，是真踩过的人才写得出的细节。乙的"拿 MCP 硬塞进一堆本该是文档的东西"是同一个意思的模糊版。

**AI 腔。** 乙有两处硬伤。一是「真正的分工不是"谁功能强"，是谁该管"何时该做"」，标准的 not-X-but-Y 两拍铺垫，节奏是造出来的、信息没多给。二是结尾"判断标准就一句话：需要连接，用 MCP；需要判断，用 Skill"——对仗口号收尾，读着爽，但把前面已经说清的东西又工整地说了一遍，是 AI 最爱的升华动作。甲也有"本质是……本质是……"的对仗和"活的、有状态、能来回交互"三连，整齐了点，但收尾"两个都是错的方向"是硬邦邦地停住，没有升华，符合反高潮。

**判断。** 甲不只给了分类，还给了一句可直接拿去用的决策问法——"这次要新增行动能力，还是要注入已有判断力"，并且指名道姓说两种错法都是错的方向，态度是关死的。乙的判断停在"需要连接用 MCP，需要判断用 Skill"，正确但没有增量，属于读者本来就猜得到的那句。

## 结论

**发甲。差距明显，不是接近。**

甲赢在两个不可替代的地方：开场有对抗性、结尾不升华，中间那个"行动能力 vs 已有判断力"的决策问法是全篇唯一一句读者能立刻带走用的东西。乙读起来更顺、排版更干净，但顺是因为它走的是标准三段式，而且带着一个会被目标读者当场抓包的技术错误。

发之前改两处：一是把"放那等你触发"改成"Claude 自己判断什么时候读它"，堵上唯一那个技术松口；二是字数，甲实际约 280 字，超了 260，从第二段的"本质是运行时的能力扩展"和"本质是 prompt 工程的组织方式"里各砍一句对仗即可，砍完反而更不整齐、更像人写的。另外正文里的半角逗号统一成全角。
