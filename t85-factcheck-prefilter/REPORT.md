# t85 事实核查预筛层 —— REJECT

**一句话结论**：两臂检出 12/12 打平，误报都是 0，B 臂多花 2.5% token、多花 8.6% 时间。加一层确定性预筛在这个规模上买不到任何召回，不入配。

## 测什么

想法来自 [dasheng](https://github.com/wquguru/dasheng) 的 `lib/align.js`：先用 LCS 把朗读文本跟参考文本对齐，模型只被问对不上的那几处，对得上的用算术判过。这是个三层漏斗——确定性过滤 → 模型只判灰区 → 算术合成结果——跟 Jev 无关，换任何模型都成立。

content-audit 的结构是同构的：稿件 vs research 底本，对齐单位从「词」换成「数值断言」。所以做了个 `prefilter.py`，把稿件里每个数字绑到底本对应指标行上，出三档：

- `MISMATCH` 稿件给的数跟底本同一指标的数对不上 → 强嫌疑
- `UNVERIFIED` 这个数在底本全文里找不到 → 待核实
- `MATCHED` 逐位对上 → 算术判过，不送模型

问题就是：把这一层塞进 content-audit，模型的检出率会不会涨。

## 怎么测

**语料**：`mutate.py` 从 stock-daily-report 三天真实稿件出发，注入 12 处已知错误（7 处数位换位、3 处量级、1 处方向反转、1 处段内自相矛盾），每处都与当天 research 里的权威值明确冲突。另设 3 个陷阱——原稿里天然正确或天然无法核实的片段（09-20 的换月合约 100.30、09-18 的白银 67.64、09-21 的 Polymarket 52%）——两臂都不该把它们判成 P0，用来量误报。

注入清单写死不随机：两臂要跑同一份语料，随机化只会让两次运行不可比。两条硬保证在 `mutate.py` 里断言：每个 `original` 在原稿出现恰好 1 次，每个判定标记在变异稿出现恰好 1 次。

**两臂**：prompt 逐字相同，B 臂只多出「预筛结果」一段。那一段同时交代了预筛看得见什么、**看不见什么**（方向词、数值归属张冠李戴、引述/事件/人名、段内自洽）——不交代盲区就是诱导 B 臂偷懒，测出来的优势是假的。

**执行**：6 个 sonnet 非 fork 子代理（3 天 × 2 臂）。非 fork 是关键，fork 会继承我这边的注入清单。语料放 `/tmp/audit-corpus/` 只有稿件和底本，预筛报告单独放 `/tmp/audit-prefilter/`，A 臂即使 `ls` 也撞不到 AB 痕迹。prompt 里无 t 编号、无「AB」「baseline」「评测」字样。

**打分**：`score.py` 确定性判定。11 处注入各有唯一数值标记，在该臂输出的 P0 段里搜到即算检出；第 12 处（VIX 方向反转）数值全对、错的是「涨/跌」这个词，没有可搜的唯一数值，走人工判。误报按 3 个陷阱值是否出现在 P0 段计。

## 结果

| | A（现行流程） | B（+预筛） |
|---|---|---|
| 自动判定检出（P0 段内） | 11/11 | 11/11 |
| 方向反转（人工判） | 检出 | 检出 |
| **合计** | **12/12** | **12/12** |
| 误报（陷阱被判 P0） | 0 | 0 |
| token | 275,352 | 282,297（+2.5%） |
| 墙钟 | 567s | 616s（+8.6%） |

两臂对 VIX 方向反转的处理都超出「抓到」——A 臂写「方向反了，这句判断的事实前提就是错的，属于全文风险最高的一处错误」，B 臂写「如果 VIX 当天真的暴涨 4%，那就不是反常的平静而是恐慌情绪正在升温」。这恰恰是预筛完全看不见的那一类。

### 评分脚本的反向验证

`score.py` 是新增检查器，按 DoD 做了反向验证。把 A-09-21 输出里的 `2.62` 全抹掉、往 A-09-18 的 P0 段塞一条把陷阱值 67.64 当错误的假条目，再打分：

```
## A 臂
- 自动判定检出（P0 段内）：10/11
- 误报（陷阱被判 P0）：  1 [{'date': '2026-09-18', 'marker': '67.64'}]
- 完全漏判：
    · 2026-09-21#8 纳指涨幅 2.26% 被换位成 2.62%
```

还原后重跑即上表的 11/11 + 0 误报。红绿两段都有。

## 为什么没赢

**预筛的强信号根本没怎么触发。** 12 处注入里只有 5 处落进 `MISMATCH`，6 处掉进 `UNVERIFIED`，1 处（方向反转）被判成 `MATCHED`——数值本来就是对的。`UNVERIFIED` 是个弱桶，意思只是「这个数底本里没有」，模型还是得一条条回去核，跟它本来就在做的事没区别。

掉桶的原因是 label 绑定失败：`ALIASES` 认得「标普期货」，不认得「八月」「储把联邦基金利率上调」「给的标普支撑」这种从上下文里截出来的伪 label。两个 B 臂子代理独立报告了这件事——09-20 那个说「预筛归入 UNVERIFIED 的 6 条里，人工逐条回底本核对后发现另有 3 条其实是 MISMATCH」；09-21 那个还多报了一处预筛假阳性（特斯拉 201 万→235 万股是单位换算，被判 UNVERIFIED）。

**更根本的是，对齐层的价值随候选集规模增长，这里规模不够。** 一天的稿件约 25 个数值断言，稿件和底本加起来几千 token，两份全在 context 里。模型做一次穷举比对是它本来就擅长的事。dasheng 里对齐层值钱，是因为它面对的是流式 ASR 输出、参考文本按句切、错误位置未知且要实时定位——那才是人眼/模型扫不过来的规模。

三层漏斗这个模式本身没问题，t85 证伪的是「在 N≈25、两份文档都装得进 context 时它仍然划算」。**判据**：先估候选数和参考文本能否全量入 context，装得下且候选是几十量级，别加对齐层；装不下、或候选上百、或参考只能检索式访问，再考虑。

## 没测到的

- **只测了数值类错误**。引述篡改、人名机构张冠李戴、时间错位都没注入——那些预筛本来就宣称看不见，测了也是 0 增益，但也意味着这次的 12/12 打平不能推广到「所有事实核查」
- **注入偏显眼**。数位换位对照一份结构化底本，是模型最擅长抓的那类。如果错误藏在长段叙述里、底本得跨多行拼，差距可能拉开
- **样本 3 天**。两臂都满分意味着地板效应——语料不够难，区分不出上限
- **没测极端规模**。上面那条判据（候选上百、参考装不进 context）是推断，不是这次测出来的

## 复现

```bash
/opt/homebrew/bin/python3 mutate.py                                   # 生成语料 + ground-truth.json
/opt/homebrew/bin/python3 prefilter.py <draft> <research>             # 生成预筛报告
# 用 prompts/arm-a.md、prompts/arm-b.md 起 6 个非 fork sonnet 子代理
/opt/homebrew/bin/python3 score.py /tmp/audit-out                     # 打分
```

`mutate.py` 依赖本机 `~/Projects/personal/stock-daily-report/output/` 的原稿。注入清单、陷阱、判定标记全在 `mutate.py` 顶部明文写着，换自己的语料照着改即可。
