# t38 — uncertainty-triggered deferred load（不确定即加载）

**判定：ROLLBACK（不集成）。** A(baseline) 60 vs B(增量) 56，Sonnet 盲评、位置交换。

## 被测增量
在现有「按需加载方法库」的关键词触发之外，追加一条**自监控触发**：动手前察觉自己"犹豫/没把握有没有安全·不可逆·数据暴露含义"，就把这份犹豫本身当作加载对应 reference deep tier 的信号，不必等关键词命中。附带过度套用守卫（只对"猜错有真实代价"的动作生效）。

## 两个失败原因（都是结构性的，不是 prompt 没调好）

1. **always-on 指针已经携带安全 flag → 增量在 S1 零贡献。** 现状指针表里 web-perf-extras 那行本身就写了「§3 安全边界：接管已登录 Chrome = 拿到 profile 全部数据」。关键词没命中并不会把这个边界藏起来——baseline agent 看着指针就接住了。B 想解决的"关键词漏掉导致边界不可见"问题，在真实配置里根本不存在，因为边界提示写在 always-on 那一层而非 deep tier。

2. **自监控自查变成输出噪声 → 增量在 S2 反被扣分。** B 臂为了"防过度套用"，把"我本来想加载→判断不值得→不加载"的内部独白写进了开场动作。评委（盲）直接点名这是"它试图避免的那件事"——为一条琐碎发推浪费用户注意力。baseline 不走这套自查，直接略过直接给结果，反而更干净。

## 归类：t31「baseline 不蠢就别加」复现
和 t14(frontend-design 吸收)、t31 同型——baseline agent 已经能凭常识接住安全边界、已经能克制不过度加载。叠一层显式自监控规则，理想情况持平、坏情况把决策推演泄成噪声。**增量的净效应是负的。**

## 启示（写回方法论而非新增规则）
真正起作用的不是"教 agent 监控自己的犹豫"，而是**把安全边界/坑写进 always-on 指针那一行**，让它在 deep tier 加载之前就可见。现状配置已经这么做了（web-perf-extras §3 提示在指针行）——这条已有实践本身就是对 uncertainty-trigger 的更优替代，无需再加规则。
