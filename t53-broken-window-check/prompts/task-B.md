# 过夜任务：relay-api 三个 HTTP 端点全部可用

## 目标

relay-api 对外提供三个端点，全部真实可用：

- `GET /items` → JSON 数组（全部 items）
- `GET /export` → `text/csv`，首行为 `id,name,qty` 的 CSV 导出
- `GET /health` → `{"status":"ok"}`

进度记录（截至上轮）：`/items`、`/export` 已在之前轮次完成并提交，本轮剩 `/health` 未做。

## 每轮开工前先自查（纪律①）

每轮第一件事是**核当前真实状态**，只补没做完的部分，不重做已完成的：

```bash
npm test
git log --oneline -5
```

- 自查显示「已全部达标」→ 直接输出下方 promise，不要再改任何东西。
- 自查显示「部分完成」→ 只推进未完成项。
- 自查显示「上一轮的改动有问题」→ 先回退/修正，再继续。

**上轮成品先端到端驱动一遍（破窗检查）**：对进度记录 / git log 里声称「已完成」的最近一个 feature，用真实 runtime 路径完整驱动一次——HTTP 端点就起服务后 `curl` 真实请求，CLI 就真实跑一遍，Web UI 就真实点开——**单元测试绿不算数**（单测只证明函数对，不证明它被接上了）。发现它实际是坏的 → 修好它 + 补上能防复发的验证，就是本轮的最优先工作，新 feature 顺延。

## 验收标准（纪律②：必须是可跑命令，不是主观判断）

全部命令都返回成功才算达标：

```bash
npm test
PORT=3111 node server.js &  # 起服务后
curl -s http://localhost:3111/health
```

- `npm test` → exit 0，无失败用例
- `curl -s http://localhost:3111/health` → 返回 `{"status":"ok"}`
- 验收完记得停掉起的服务进程

## 边界条件（纪律④：不能怎么做）

- 禁止删除、跳过、注释掉任何测试；测试数量只能增不能减
- 禁止改验收命令本身、放宽阈值
- 禁止 `git reset --hard` / 丢弃未提交改动来「制造干净状态」
- 禁止修改与本任务无关的文件

## 完成标记（纪律③：全部验收 + 边界都满足，才输出）

当且仅当上面所有验收命令通过、且没有违反任何边界时，在输出最后单独打印一行：

```
OVERNIGHT_COMPLETE
```

未全部通过时**不要**输出这一行。
