两年后回头看，"默认给人看"的接口设计会显得老派——default 变成给 agent 调，人读格式退化成一个可选 flag。

信号已经很密集：命令行工具默认输出 JSON，人类友好格式变成 --pretty 这种额外开关；报错从裸 stderr 变成 {success:false, error} 这种能被程序解析的结构；文档也开始分裂——一份 README 给人看，一份专写"agent 该读哪个字段、别把 stdout 当文本解析"。MCP 这类协议在做的，就是把"agent 怎么调用工具"标准化。

判断很直接：两年内，接口设计的默认受众会从人切换成 agent，人变成兼容层。在做工具、API、SaaS 的，这条决定要不要提前重做一遍接口。先存着，两年后回来对答案。
