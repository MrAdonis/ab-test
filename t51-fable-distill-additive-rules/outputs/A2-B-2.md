这段代码有一个致命问题和几个中等问题，本周上线前必须处理。

## P0：`/dev-login` 是无认证的账户接管后门

```js
router.post('/dev-login', async (req, res) => {
  const user = await User.findOne({ email: req.body.email });
  req.session.userId = user.id;
  res.json({ ok: true, as: user.email });
});
```

任何人只要 POST 一个 `email`，不需要密码就能拿到该用户的 session，等于任意账户接管。而且这条路由和 `/login` 挂在同一个 router、同一个文件里，没有看到任何环境判断（`NODE_ENV`/开关变量）——如果这个 router 被原样挂载到生产 app 上，生产环境就直接可被利用。

必须按 P0 处理，不是"有点不严谨"，是可以直接被脚本化批量接管全站账号的漏洞。

修复方式，二选一：
1. **彻底不要放在会被生产加载的路由文件里**。挪到单独的 dev-only 路由模块，只在本地/测试 server entry 里 `require`，生产入口完全不引用这个文件。
2. 如果一定要留在同一文件，必须显式环境门控 + 密钥双重保险，两者缺一不可：

```js
router.post('/dev-login', async (req, res) => {
  if (process.env.NODE_ENV === 'production' || !process.env.ALLOW_DEV_LOGIN) {
    return res.status(404).end(); // 而不是403，避免暴露端点存在
  }
  const user = await User.findOne({ email: req.body.email });
  if (!user) return res.status(401).json({ error: 'invalid credentials' });
  req.session.userId = user.id;
  res.json({ ok: true, as: user.email });
});
```

且 `ALLOW_DEV_LOGIN` 这类开关绝对不能出现在生产环境变量配置里，最好上线前在 CI 里加一条硬性检查（grep 生产 env 或者部署清单里没有这个变量）。

## P1：`/dev-login` 还有额外 bug

`User.findOne` 查不到用户时 `user` 是 `null`，`user.id` 直接抛未捕获异常、进程可能因未处理的 rejection 挂掉（取决于你们全局错误处理）。就算做成 dev-only，也该判空。

## P2：`/login` 本身的问题

- **没有限流/失败锁定**：暴力破解密码没有任何阻拦，建议加 `express-rate-limit` 或类似机制（按 IP + 按账号维度都做）。
- **时序侧信道**：`findOne` 找不到 user 时直接短路返回 401，不会执行 `bcrypt.compare`，而找到 user 会执行。这会造成"邮箱是否存在"的响应时间差异，可用于枚举注册邮箱。建议无论是否找到用户都执行一次 bcrypt 比较（比如用一个固定的假 hash 兜底），保持时间恒定。
- **session 固定攻击**：登录成功后没有看到 `req.session.regenerate()`。如果 session 中间件配置不当，攻击者可能诱导受害者使用已知 session id 登录后直接窃取该 session。建议：

```js
req.session.regenerate(err => {
  if (err) return res.status(500).json({ error: 'server error' });
  req.session.userId = user.id;
  res.json({ ok: true });
});
```

- 没看到 `email`/`password` 的输入校验（非字符串、超长字符串等），以及没看到全局 `express-mongo-sanitize`（如果用 MongoDB，`email` 是对象时 `findOne` 可能被 NoSQL 注入，比如 `{"$gt":""}`）。确认一下 body-parser 之上有没有做类型/schema 校验（推荐 zod/joi 之类）。

## 结论

`/dev-login` 是本周上线前的阻塞项，不修好不能合并到会打包进生产的分支/路由文件。其余几项建议一并解决，成本都不高。
